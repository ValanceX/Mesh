# MESH v0.3 Pass 0: Groundwork Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build what every later v0.3 pass consumes, and close the audit's small open findings (outline, "Pass 0 — Groundwork and audit follow-ups"). This pass:
- adds the **source map** (D2): one public, total mapping between byte offsets and line/column positions in `char`, UTF-8 and UTF-16 units, and moves both renderers onto it with no change in output;
- adds **offset queries** over `mesh_analysis::Analysis` (A9): the resolution, the typed expression and the facts at a byte offset;
- records a **span for every manifest declaration** (D5), in a side table that leaves the model's value types untouched;
- stops `mesh check` **panicking on a closed stdout** (A5);
- renames the npm placeholders to **`@valance/*`** (D11), and trims `packages/mesh-lsp`, the `mesh-lsp` crate and the docs to v0.3's scope (A11);
- rewords the manifest **compatibility promise** and both **depth messages** so that a resource limit reads as MESH's supported limit, not a rule of the format (D12).

**Architecture:**
- **`mesh-compiler`** gains a public `source_map` module: `SourceMap`, `ColumnUnit` and `LineColumn`. It replaces the private `position::locate`, which becomes a thin adapter or goes away. `render_diagnostic` and `render_json` use it. It is compiler infrastructure: `mesh-lsp` will consume it, and nothing in it knows about LSP.
- **`mesh-analysis`** gains three read-only queries on `Analysis`. Analysis itself doesn't change: the queries search the lists it already keeps.
- **`mesh-manifest`** gains `Declaration<'a>` and `Manifest::span_of`, backed by a map that `validate.rs` fills from the spans it already has while it validates.
- **`mesh-cli`** writes through fallible writers, and treats a broken pipe as "the reader went away", not as a crash.
- Tasks **P0.1**–**P0.6**, in that order. P0.5 and P0.6 are independent of the others and of each other.

**Tech Stack:** Rust, on the pinned toolchain (1.98.1; MSRV 1.91). No new dependency. No new diagnostic code: `DiagnosticCode::ALL` is unchanged.

**Spec:** `docs/superpowers/specs/2026-09-24-mesh-v0.3-outline.md`: invariants I1 and I4; D2, D5, D11, D12; findings A5, A6, A9, A10, A11, A13, A14; the Definition of Done's "Positions are exact" item, which this pass fully owns.

**Verification evidence:** unlike the v0.2 plans, this plan was **not** implemented in a scratch worktree before it was written. The facts it relies on were checked against the code at `686f3f0`: the current `locate` rules and their tests, `render_json`'s document shape, the manifest validator's structure, every `@valence` reference, and the depth messages and their fixtures. ## Decisions this plan makes

**Source map (P0.1)**

1. **The public type is `mesh_compiler::SourceMap`,** built with `SourceMap::new(source: &str)`. It owns a copy of each line's start offset (a `Vec<usize>`) and borrows nothing, so a server can keep it beside a snapshot's text without lifetime ties. It lives in `mesh-compiler`, beside the renderers that already need it, as the outline recommends; a separate crate buys nothing yet.
2. **Positions are 0-based in the API** (`LineColumn { line, column }`), because LSP is 0-based and the renderers add one in exactly two places. The renderers' 1-based output doesn't change.
3. **Three column units:** `ColumnUnit::Char` (the CLI and JSON), `ColumnUnit::Utf16` and `ColumnUnit::Utf8`. There is no `Utf32` unit: it is the same count as `Char`, and LSP's `utf-32` encoding maps to `Char`. `mesh-lsp` does that mapping, not the source map.
4. **The rules are total, and they are exactly today's `locate` rules extended to reverse mapping:**
   - A line ends at `\n`. A `\r` immediately before it isn't part of the line's text, so LF and CRLF give the same columns.
   - A **lone `\r`** is ordinary text, as it is in today's output. LSP treats a lone `\r` as a line break; files with one would have positions that disagree with the editor's. That's a documented limitation, not something this pass changes: changing it would change `mesh check`'s line numbers. The source map's rustdoc and the CLI manual say so.
   - A leading byte-order mark isn't text: an offset on it is line 0, column 0.
   - `line_column(byte, unit)`: an offset past the end clamps to the end; an offset inside a UTF-8 sequence floors to its character; an offset inside the line ending is just past the line's last visible character.
   - `offset(position, unit)`: a line past the last clamps to the end of the file; a column past the end of the line's text clamps to the end of that text (before any `\r`); a UTF-16 column inside a surrogate pair floors to the start of the character; a UTF-8 column inside a sequence floors the same way.
5. **Zero-width spans** need no special case: a span maps through its two ends, and equal ends give equal positions. A test pins it anyway, because D2 lists it.
6. **`line_text(line) -> Range<usize>`** gives the byte range of a line's visible text (no BOM, no `\r`, no `\n`). The terminal renderer needs it for its snippet.
7. **Cost:** `new` is O(n). `line_column` is O(log lines + line length), by binary search over line starts, then by counting within the line. A line index per column unit would be faster, but lines in MPRX are short. `render_json` and the renderer build one `SourceMap` per call. That fixes A6's O(n·m) and needs no API change.

**Offset queries (P0.2)**

8. **Three queries,** each taking a byte offset:
   - `Analysis::resolution_at(offset) -> Option<&Resolution>`;
   - `Analysis::typed_at(offset) -> Option<&Typed>`;
   - `Analysis::facts_at(offset) -> impl Iterator<Item = &Fact>`.
9. **"At" includes both ends:** `span.start_byte <= offset && offset <= span.end_byte`, so a cursor just after `user` still finds `user`. Where several spans contain the offset, the innermost wins: the shortest span. Two different spans of equal length can only both contain an offset where one ends and the other starts, and then the one that starts later wins, so the result is always defined. `facts_at` returns every containing fact in `facts()` order.
10. **`type_at(span)` stays** as it is; the new query sits beside it, as the outline says.

**Declaration spans (P0.3)**

11. **A side table, not fields on the model.** Putting a `span` on `Field` would make two `Type::Record`s with the same meaning compare unequal when they were written in different places, and `load.rs` compares `Type` values by equality. So `Manifest` keeps a private `BTreeMap<DeclarationKey, Span>`, and `Manifest::span_of(Declaration<'_>) -> Option<Span>` reads it.
12. **The span is the declaration's key, quotes included**, like `manifest-duplicate-key` reports: `"avatar"` for a component, `"alt"` for a prop. For a parameter, which has no key, it is the parameter's `"name"` value.
13. **`Declaration` covers what go-to-definition and hover can name:**
    - `Component(name)`;
    - `Prop { component, prop }`, `Event { component, event }` and `Command { component, command }`;
    - `Parameter { component, command, index }`;
    - `Scope { component, name }`;
    - `NamedType(name)`;
    - `Field { ty, field }`: a field of the named record type `ty`.

    Fields of anonymous records nested inside other types have no name to address them by, so they are not in the table. Nothing in v0.3 needs them.
14. **`#[non_exhaustive]`** on `Declaration`, so v0.4 can add variants.

**The CLI (P0.4)**

15. **A write to a closed stdout or stderr ends output quietly.** Each write goes through `writeln!` on a locked handle. The first `BrokenPipe` error stops further output, and the process exits with the status the check already determined (0 or 1). Any other I/O error is reported once on stderr, if stderr still works, and exits 1. Rust ignores `SIGPIPE`, so the write returns `EPIPE` rather than killing the process; this relies on that default and doesn't change it.

**Packages and docs (P0.5)**

16. **Every package and every reference moves to `@valance/`,** including the inter-package dependencies. The versions stay `0.0.1`; nothing is published.
17. **`packages/mesh-lsp` becomes a launcher's placeholder.** It loses its `vscode-languageserver` dependency and its dependency on `@valance/mesh-compiler`. Its description says it will launch the Rust `mesh-lsp` binary. Its `bin` entry stays, for v0.4 to fill in.
18. **The `mesh-lsp` crate's doc** lists v0.3's features (diagnostics, quick fixes, hover, go-to-definition, completion) and says it is a client of `mesh-compiler`. ARCHITECTURE.md's `mesh-lsp` bullet drops references, rename, document symbols and formatting in the same way.

**Wording (P0.6)**

19. **The messages** become exactly the outline's D12 wording:
    - `nesting-too-deep`: `this is nested more than 128 levels deep, the deepest MESH supports`;
    - `manifest-nesting-too-deep`: `the manifest nests arrays and objects more than 128 levels deep, the deepest MESH supports`.

    Codes don't change.
20. **The manifest reference's "Versions" section** gains this sentence after its promise: "The promise covers what a manifest means and whether the format allows it. An implementation's documented resource limits, such as the nesting limit, are not part of the format, and a version of MESH may change them." The existing paragraph under "Validation" that already says the limit belongs to MESH stays. The spec's "Nesting limit" paragraph and the diagnostics reference get the same framing.

**Deferred**

21. **A13 (related spans) is not in this pass.** The outline makes it "only if cheap", and no v0.3 feature depends on it. It's a small change best made when something wants it, for example alongside Pass 2's hover.

## Review Focus

1. **Output didn't move.** Every fixture `.stderr` except the two P0.6 rewrites, all renderer and JSON tests, and the JSON/human corpus agreement test pass unedited after P0.1.
2. **Positions are exact** (the outline's DoD item). `source_map` tests cover, in each direction and each unit: an offset inside a 2-, 3- and 4-byte character; a UTF-16 column inside a surrogate pair (`😀` is 4 bytes, 1 char, 2 UTF-16 units); offsets at and past the end; a column past the end of a line; a zero-width span; LF, CRLF and a lone `\r`; a leading BOM; an empty source. A round-trip property test shows that `offset(line_column(b))` equals `b` floored to a character boundary, for every byte of a mixed corpus.
3. **One definition of a position.** The grep in Global Constraints finds nothing, and `render_json`'s `line`/`column` still equal the human `-->` for every corpus run.
4. **Innermost wins.** On `examples/users-page.mprx`: at the `n` of `user.name`, `typed_at` gives the member access's `string`, and `resolution_at` gives nothing (a member is not a resolved name). At the `u`, `resolution_at` gives `Scope("user")`, and `typed_at` gives the reference's `User`. At `alt`, `resolution_at` gives `Prop { avatar, alt }`.
5. **Every declaration has its key's span.** For every component, prop, event, command, parameter, scope name, named type and named-record field in `examples/components.json`, `span_of` returns the span whose text is the quoted key. For an undeclared name, it returns `None`.
6. **A closed pipe is not a crash.** `mesh check --format json` on a file with thousands of errors, with its stdout closed before it writes, exits 1 with no `panicked` on stderr. The same holds for human output with stderr closed.
7. **No `@valence` left** outside history: the only matches are in `docs/superpowers/` and the CHANGELOG's past entries, if any. A test pins every `packages/*/package.json` name and dependency to `@valance/`.
8. **The wording is consistent.** Both fixtures, the diagnostics reference's examples (pinned by the drift test) and the manual's prose describe a supported limit.

  ```rust
  pub struct SourceMap { /* line starts, text length, BOM length */ }
  #[derive(Debug, Clone, Copy, PartialEq, Eq)]
  pub enum ColumnUnit { Char, Utf8, Utf16 }
  #[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
  pub struct LineColumn { pub line: usize, pub column: usize }

  impl SourceMap {
      pub fn new(source: &str) -> SourceMap;
      pub fn line_column(&self, source: &str, byte: usize, unit: ColumnUnit) -> LineColumn;
      pub fn offset(&self, source: &str, position: LineColumn, unit: ColumnUnit) -> usize;
      pub fn line_text(&self, source: &str, line: usize) -> std::ops::Range<usize>;
      pub fn line_count(&self) -> usize;
  ```
