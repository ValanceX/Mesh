# MESH v0.4 Pass 0: Groundwork Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Settle the four contracts Pass 1 and Pass 2 build on (outline, "Pass 0 — Groundwork"), in the outline's order:
1. the **compiler-level check operation** (D3, E1): `mesh-compiler` owns the batch check, and the CLI becomes a host of it with unchanged output;
2. the **UTF-16 diagnostic contract** (D5, E3): every position in the diagnostics document also gives its UTF-16 offset and column, computed by `SourceMap`;
3. the **native platform test baseline** (D9, E6): `cargo test --workspace` on Linux, macOS and Windows, and whatever the first macOS and Windows runs find;
4. the **npm workspace and package clean-up** (D7, E4, E5): the `@valancex` scope, two packages, a workspace with a lockfile, no undeliverable `bin`, and version lockstep.

**Architecture:**
- **`mesh-compiler`** gains a public `check` module. It holds the rules that today live in `mesh-cli`'s `run_check`, as two phases (load a model; check a source against it) and one function that runs both. The CLI calls the phases, the WASM build (Pass 1) calls the one-shot function, and a test proves they agree.
- **`SourceMap`** gains one query, the UTF-16 offset of a byte, so the JSON renderer takes both new properties from it (I4).
- **CI** splits into a Linux lint job and a three-OS test job.
- **`packages/`** becomes an npm workspace holding `@valancex/mesh-compiler` and `@valancex/mesh-lsp`.
- Tasks **P0.1**–**P0.4**, in that order. P0.2 depends on nothing in P0.1, but the outline orders the contracts, and P0.3's first Windows run should exercise both.

**Tech Stack:** Rust on the pinned toolchain (1.98.1; MSRV 1.91). npm, with TypeScript as a workspace dev dependency. No new Rust dependency. No new diagnostic code: `DiagnosticCode::ALL` is unchanged.

**Spec:** `docs/superpowers/specs/2026-09-25-mesh-v0.4-outline.md`: invariants I4–I7 and I9; D3, D5, D7, D9, D11; findings E1, E3, E4, E5, E6. This pass fully owns the Definition of Done's "Positions work in JavaScript" item on the Rust side (Pass 1 repeats it in JavaScript) and the scope, list and version parts of "The packages are what we say they are".

**Verification evidence:** the facts this plan relies on were checked against the code at `7875097`: `run_check`'s flow and the manual's promise that a broken manifest "stops without reading `<FILE>`" (`docs/manual/mesh-cli.md`); `mesh_manifest::load` returning an owned `Manifest`, and `Manifest::template` returning `Result<Template<'_>, Diagnostic>`; `render_json`'s `Position` and the schema's `position` definition (`additionalProperties: false`); every test that pins JSON text (`crates/mesh-compiler/tests/json.rs`, `the_cli_manuals_json_example_is_what_mesh_prints` in `crates/mesh-cli/tests/check.rs`); `lsp_agreement.rs` reading only `byte` from JSON positions; `crates/mesh-cli/tests/packages.rs`; `.gitattributes`; and CI. ## Decisions this plan makes

**The check operation (P0.1)**

1. **A public module, `mesh_compiler::check`,** holding:

   ```rust
   /// A manifest that loaded cleanly, and a component it declares.
   pub struct Model { /* manifest: mesh_manifest::Manifest, component: String */ }

   impl Model {
       /// Loads `manifest` and looks up `component`. On failure, the
       /// diagnostics are reported against the manifest: every manifest
       /// error, or else the one `manifest-missing-component`.
       pub fn load(manifest: &str, component: &str) -> Result<Model, Vec<Diagnostic>>;
   }

   /// Checks `source` as the template of the model's component, or with
   /// no model. The diagnostics are reported against `source`.
   pub fn source(source: &str, model: Option<&Model>) -> Vec<Diagnostic>;

   /// Every input of one check, for a host that has them all up front.
   pub struct Request<'a> { pub source: &'a str, pub path: &'a str, pub model: Option<ModelInput<'a>> }
   pub struct ModelInput<'a> { pub manifest: &'a str, pub path: &'a str, pub component: &'a str }

   /// Which document a report's diagnostics are reported against.
   pub enum Document { Source, Manifest }

   #[non_exhaustive]
   pub struct Report { pub document: Document, pub diagnostics: Vec<Diagnostic> }

   /// `Model::load`, and if it succeeds, `source`: the whole check.
   pub fn run(request: &Request<'_>) -> Report;

   impl Report {
       pub fn has_errors(&self) -> bool;          // any `Severity::Error`
       pub fn render_json(&self, request: &Request<'_>) -> String; // against the right text and path
   }
   ```

   `Request`, `ModelInput` and `Document` are `#[non_exhaustive]` where a later field is plausible (`Request`, `ModelInput`), with constructors, so hosts don't build them with struct literals.
2. **Two public phases, and a one-shot function made of them.** The CLI must keep its documented promise that a broken manifest "stops without reading `<FILE>`": it can't read the file before the model is known to load, so it can't hand every input to one function. The phases carry the rules (a model exists only if the manifest loaded and declares the component, so "manifest errors stop the check" is enforced by the types); `run` is exactly `Model::load` then `source`, and it is what WASM calls. The CLI calls the same two phases in the same order, with its file read between them. Nothing else in the CLI decides anything about a check.
3. **`Report::render_json` picks the text and path,** manifest or source, from `Report::document`. A host never chooses which text to render against, so it can't choose wrong.
4. **The component is always explicit** in `Model::load` and `ModelInput` (I5). The CLI's stem default stays in the CLI, before the call.
5. **`has_errors` is the exit rule's input,** not the exit rule: exit codes are the CLI's presentation. Warnings still don't fail the check.
6. **No new behaviour.** `source(text, None)` is `compile(text).diagnostics`; `source(text, Some(model))` is `compile_with` with the model's template. The check module adds no rule of its own.

**UTF-16 positions (P0.2)**

7. **Two new properties on every position:** `"utf16"`, the 0-based offset in UTF-16 code units into the source exactly as given, a byte-order mark included (so it corresponds to `byte`, not to `column`); and `"utf16Column"`, the 1-based column in UTF-16 code units, with exactly `column`'s rules (a BOM and a line's `\r` aren't columns). The offset is what `String.prototype.slice` and CodeMirror take; the line and UTF-16 column are what Monaco takes. The names are camelCase because their audience is JavaScript; the existing single-word names are unaffected.
8. **`SourceMap::utf16_offset(&self, source: &str, byte: usize) -> usize`** is the one new query. It floors `byte` to a character boundary and clamps it to the end, exactly as `byte` itself is meaningful, then counts UTF-16 units from the start of the source. `SourceMap::new` records each line start's UTF-16 offset once, so the query costs O(log lines + line length), like `line_column`. `utf16Column` comes from the existing `line_column(.., ColumnUnit::Utf16)` plus one.
9. **The schema adds both properties to `position`,** with descriptions, and to its `required` list: the schema describes exactly what this MESH prints, and its description already tells consumers to ignore properties they don't know. `version` stays 1.
10. **Human output doesn't change,** and neither does `mesh-lsp`, which converts positions from bytes through `SourceMap` already.

**The native test baseline (P0.3)**

11. **CI becomes two jobs plus MSRV.** `lint` (Ubuntu): fmt, clippy, rustdoc, the grammar's npm tests and the regenerated-parser check, exactly today's steps. `test`: `cargo test --workspace` on a matrix of `ubuntu-latest`, `macos-latest` and `windows-latest`, `fail-fast: false`. `msrv` stays as it is. The whole suite runs once per OS, not per architecture (outline D9).
12. **All text is LF in every checkout.** `.gitattributes` gains `* text=auto eol=lf` above its existing rules. Tests read docs (`diagnostics_reference.rs`, `editor_setup.rs`, `check.rs`'s manual test) and compare text; a Windows checkout with `core.autocrlf=true` would otherwise hand them CRLF. The existing fixture and capture rules stay, as documentation of why those files matter most.
13. **What the first runs find is fixed at its cause.** Expected suspects, from reading the code: `Path::canonicalize` returning `\\?\C:\...` verbatim paths on Windows (used in `lsp_agreement.rs` and `fuzz.rs` to build URIs with `file_uri`); `uri.rs`'s handling of drive letters; paths printed with `\` where a test expects `/`; process exit codes in `transport.rs`. A product bug (in `mesh-lsp`, `mesh-cli`) is fixed in the product, with a test that runs on every OS and a CHANGELOG entry. A test-only assumption is fixed in the test. Nothing is skipped (Global Constraints).
14. **CI runs on the branch.** `ci.yml` runs on pushes to `main` and on pull requests. P0.3 adds `workflow_dispatch`, so the branch can be run without a PR. If dispatching isn't available to the session, open a draft PR for the branch, with the user's go-ahead.

## Review Focus

1. **The CLI decides nothing.** `run_check` reads files, derives the component from the stem, calls `check::Model::load` and `check::source`, renders, and maps `has_errors` to the exit status. `git grep -n "mesh_manifest::load\|\.template(" crates/mesh-cli/src` finds nothing.
2. **The phases and `run` agree with the CLI.** For every corpus run `fixtures.rs` makes, `check::run(..).render_json(..)` equals `mesh check --format json` for the same explicit inputs, parsed (I7 at the Rust level).
3. **`source.slice(utf16, utf16)` is the span's text.** In Rust: for every diagnostic of every corpus run, and for a corpus mixing 2-, 3- and 4-byte characters, CRLF and a BOM, the UTF-16 units `utf16` delimits, decoded, equal `&source[byte..byte]`.
4. **The schema accepts exactly what's printed,** including the new properties, and rejects a position without them.
5. **Green on three OSes,** with nothing skipped, and every fix for a platform bug named in the CHANGELOG.
6. **Two packages, `@valancex`, lockstep.** `packages.rs` passes; `git grep -n "@valance/"` finds matches only in history (`docs/superpowers/`, `docs/releases/v0.3.md`, and the CHANGELOG's released sections).
