# MESH v0.3 Pass 3: Editor Recovery State — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make hover and go-to-definition work on the parts of a file that parse while another part has a syntax error, which is the state a file is in most of the time while typing (outline, "Pass 3 — Editor recovery state", finding A7). This pass implements D3's design spec, `docs/superpowers/specs/2026-09-24-mesh-v0.3-editor-recovery.md`:
- `mesh-parser` gains `recover`, an **editor-only** entry point beside `parse` that keeps what parses (rules R2–R5);
- `mesh-semantic` exposes expression lowering, and `mesh-analysis` gains `analyze_expression`, so recovered parts are analyzed by **the same analysis code** (R6), never by anything in `mesh-lsp`;
- `mesh-compiler` gains an `editor` module with `recover` and a `Recovery` that can answer `resolution_at` and `typed_at` and **cannot** produce a diagnostic (R7, P3);
- the server computes recovery on the compile thread for snapshots with no IR, keeps it beside their canonical state, and falls back to it for hover and definition (R1, R8);
- tests prove the spec's properties P1–P5, above all that recovery never changes canonical state or what is published (I2, I3).

**It does not** add completion (Pass 4; it reuses `analyze_expression` from here), change `parse`, `compile` or `compile_with`, or change any published diagnostic.

**Architecture:**

```text
mesh_parser::recover ─┐                      (editor-only; CST stays private)
mesh_semantic::lower / lower_expression ─┐   (existing lowering, now also public for one expression)
mesh_analysis::analyze / analyze_expression ─┐  (the same walker)
                             mesh_compiler::editor::recover → Recovery { parts }
                                                        │
          mesh-lsp worker: only when the canonical result has no IR and a template
```

- **`mesh-parser`**: a new module `recover.rs`. `pub fn recover(source: &str) -> Recovered`, where `Recovered { pub elements: Vec<mesh_syntax::Element>, pub expressions: Vec<mesh_syntax::Expression> }`, both `#[non_exhaustive]`. It has its own `recover_element`, shaped like `lower_element` but filtering as R4 says where that collects attributes, bindings and children, and it calls the existing leaf helpers (`lower_attribute`, `lower_event_binding`, `lower_expression_block`, `field_text`) on clean subtrees only. `lower_element` itself doesn't change, so `parse` can't. The walk that finds elements (R3) and the expression blocks R4 dropped (R5) is iterative.
- **`mesh-semantic`**: `pub fn lower_expression(&mesh_syntax::Expression) -> Expression`, the existing private function made public, unchanged.
- **`mesh-analysis`**: `pub fn analyze_expression(expression: &mesh_semantic::Expression, template: Template<'_>) -> Analysis`: a `Walker` that calls `expression(expression, Place::Value)` once, then sorts facts as `analyze` does.
- **`mesh-compiler`**: `pub mod editor` with `pub fn recover(source: &str, template: Template<'_>) -> Recovery` and `Recovery::{resolution_at, typed_at}`. `Recovery` holds `Vec<Analysis>` privately and exposes nothing else. The module's rustdoc states I2 in full.
- **`mesh-lsp`**: the worker calls `editor::recover` after the canonical compile when R1 holds; `Compiled` gains `recovery: Option<Arc<Recovery>>`; `navigate` asks the analysis if there is one, else the recovery.
- Tasks **P3.1**–**P3.6**, in order.

**Tech Stack:** Rust 1.98.1, MSRV 1.91. No new dependency.

**Spec:** the outline's invariants I1–I3, D3, D7; findings A7, B6; the recovery spec's rules R1–R8 and properties P1–P5; the Definition of Done's "It works on broken files", its hover item.

**Depends on:** Pass 2 merged (hover and definition, the held-request rule, and `CompileResult::analysis`).

**Verification evidence:** the recovery spec's eighteen shapes (S1–S18) were observed on 2026-09-24 by parsing each input with the committed grammar and dumping the complete tree. The claim that an element analyzes the same alone as in its parent was checked by reading `crates/mesh-analysis/src/check.rs`: `Walker::element` reads only `self.template`, and walks children with `self.element(child)` and expressions with `Place::Value`. The API sketches are designs, not verified code. Write each failing test first and see it fail.

## Global Constraints

- **I2 is the point of this pass.** `parse`, `compile` and `compile_with` are unchanged: `git diff <base>..HEAD -- crates/mesh-parser/src/lib.rs` touches only the `mod`/`pub use` lines and the visibility of lowering helpers, and `crates/mesh-compiler/src/lib.rs` only gains `pub mod editor`. `mesh-cli` doesn't call anything added here: `git grep -n "recover\|editor::" crates/mesh-cli/src` is empty.
- **I3:** nothing recovered is published. `Recovery` has no facts and no diagnostics; `mesh-lsp`'s publication code reads only the canonical result. The Pass 1 agreement test passes unedited, and P3.5 extends it.
- **I1:** `mesh-lsp` calls `mesh_compiler::editor::recover` and nothing below it. No resolution, type or lookup is computed in `mesh-lsp`.
- **Never panic on input** (D7). `recover` must be total on any text: no `unwrap`, `expect` or `unreachable!` on a node's shape. The existing lowering helpers `unreachable!` on shapes a clean tree can't have; `recover` calls them only on subtrees with no error (R4, R5), and P3.1's fixtures plus P3.5's prefix test exercise that.
- **Recursion is bounded** (R2): `recover` returns nothing for a tree deeper than `MAX_NESTING_DEPTH`, before anything recursive runs, and it runs on the compile thread (R8).
- **Changelog, authorship, don't push,** as in Pass 0.
- **Verification gate for every task:** Pass 0's four commands.

## Decisions this plan makes

1. **Names say "editor".** The parser's function is `recover`, in a module whose rustdoc opens: "Editor-only. Never part of `parse`, `compile` or `compile_with`, and never a source of diagnostics (outline I2)." The compiler's module is `editor`. The CLI manual doesn't mention either.
2. **`Recovered` is AST, not CST.** The CST stays private to `mesh-parser`, as the architecture requires; `Recovered` holds `mesh_syntax` values, like `ParseResult`.
3. **What an element part keeps** is exactly R4. A `container_element` whose closing tag is missing or `MISSING` gets `closing_name: None`. A tag mismatch is still lowered, and `mesh_semantic::lower`'s diagnostic about it is discarded, as all lowering diagnostics of recovered parts are.
4. **Where an element inside an `ERROR` among an element's children goes** (R4's last bullet): into the pruned element's `children`, at its position. So the recovered tree keeps its shape wherever it can.
5. **`analyze_expression` is value position.** It's the spec's rejected-alternatives choice: no handler, no handler argument. It returns a full `Analysis`, facts included, because it's the analysis crate's normal output; `editor::Recovery` then drops the facts.
6. **The recovery store.** `Recovery { parts: Vec<Analysis> }`, in source order. `resolution_at` and `typed_at` apply `Analysis`'s own innermost rule across all parts (R7): collect each part's answer and take the shortest span, the later start on a tie.
7. **When the server runs it** (R1, R8): in the worker, right after the canonical compile of the same job, only if the result has no IR and the job's model is a template. The worker returns it in `Done`; `finish` stores it in `Compiled` with the canonical result, under the same identity, so it is dropped with its snapshot and never outlives it.
8. **How navigation uses it.** `navigate` takes a small `Facts` view: the canonical `Analysis` if the result has one, otherwise the `Recovery`, otherwise nothing. Both answer `resolution_at` and `typed_at`, and hover and definition don't know which they got. When the canonical result has IR, the recovery is `None` by construction.
9. **Fixtures for the shapes** live as Rust tests in `crates/mesh-parser/tests/recover.rs`, one per S1–S18, each with the input inline and the expected parts written as a compact summary: for an element part, its tag name, kept attribute and binding names, and children (text, `{…}` or a nested summary); for an expression part, its source text. A helper renders a `Recovered` as that summary, so a failure prints the whole difference.

## Review Focus

1. **The shapes are pinned (P5):** `recover.rs` has one test per S1–S18, each passing.
2. **Recovery agrees on files that parse (P1)** (`recovery_equals_canonical_analysis_on_every_parsing_file`, in `crates/mesh-compiler/tests/editor.rs`): for every `.mprx` fixture that parses and both examples, with their corpus template, `editor::recover` has exactly one part, and at every byte offset its `resolution_at` and `typed_at` equal the canonical analysis's.
3. **Recovery never touches canonical state (P2):**
   - `compile_with_is_unchanged_by_recovery`: for every fixture with a syntax error and every prefix of both example templates, with and without their template, `compile_with`'s whole `CompileResult` is equal before and after calling `editor::recover` on the same text.
   - `every_prefix_publishes_what_mesh_check_reports` (in `crates/mesh-cli/tests/lsp_agreement.rs`): the server, configured with a model, is sent each prefix of `users-page.mprx` as a `didChange` in turn, and each publication equals `mesh check --format json` on that prefix. This is the prefix walk the outline gives Pass 5, restricted to publication; Pass 5 extends it to every fixture and adds the crash contract.
4. **Nothing recovered is published (P3):** `Recovery`'s public API is `resolution_at` and `typed_at` only (a `compile_fail` doctest shows `recovery.facts()` doesn't exist); `git grep -n "recovery" crates/mesh-lsp/src/documents.rs` shows it only stored, never converted.
5. **Misparses aren't answers (P4)** (`crates/mesh-lsp/tests/recovery.rs`): with a manifest whose template scope declares `page` and `text`, on S16's and S17's texts, hover over the closing tags' names gives `null`.
6. **The Definition of Done's hover item on broken files:**
   - `hover_works_beside_a_syntax_error`: `users-page.mprx` with `<text>{user.}</text>` added; hovering `compact` in the avatar's `size` shows `boolean`, and hovering the new `user` shows `user: User` (an expression part).
   - `hover_works_before_an_unclosed_block`: the same with `<text>{user.` and no `}`, which collapses the root (S16); hovering `compact` still works, because the avatar survives as an element part of the forest.
   - `definition_works_beside_a_syntax_error`: definition on `avatar` still lands on `"avatar"`.
   - In each, the published diagnostics are exactly the canonical syntax errors.
7. **Deep broken input** (`recovery_of_a_file_nested_too_deep_is_empty`): a file nested 200 levels with a syntax error at the bottom recovers no parts, and the worker's 8 MiB stack is never at risk.
