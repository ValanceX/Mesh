# MESH v0.2 Pass 1 Follow-ups Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the findings Pass 1 left open:
- a deeply nested file with a syntax error must be rejected with exit 1, never crash;
- the slow (about 20s) deep-nesting regression test becomes fast;
- `<page é-id="x" />` must not claim the attribute is `-id`;
- the docs must stop overclaiming, and say that `missing-closing-tag` can hide other mistakes;
- the untracked Pass 1 plan's README snippet must match the file it edits.

**Architecture:**
- **Task 1** stops the syntax-error classifier (`crates/mesh-parser/src/syntax_errors.rs`) from calling Tree-sitter's `Node::parent()`, `prev_sibling()` and `next_sibling()`.
  - In tree-sitter 0.27 each of those re-walks the tree from the root on every call. For a zero-width `MISSING` node, `ts_node_child_with_descendant` recurses once per level on the way down.
  - On a file nested more than about 3,200 levels (on a 2 MiB test thread) that overflows the stack and aborts. It is also why the depth-3,000 test takes about 20s.
  - The iterative walk in `collect` already visits every ancestor. It now keeps them in a `path` and hands each error to the classifier as a `Region { node, ancestors }`. `Region` answers `parent()`, `ancestor(n)` and `sibling(offset)` from that path.
  - No classification decision changes. Only where parents and siblings are read from changes.
- **Task 2** tightens `hyphenated_attribute_name`: the hyphenated word must start where an attribute name can start. That is after whitespace, or straight after the previous attribute's value (`"` or `}`).
  - Anything else just before the word, such as the `é` in `é-id`, is a second mistake in the same name, so the region falls back to `syntax-error`.
- **Task 3** is docs plus a pinning test:
  - qualifies "A syntax error is reported where the mistake is";
  - documents that an unclosed root hides the mistakes inside it;
  - fixes the matching README overclaim.
- **Task 4** fixes the untracked Pass 1 plan's README snippet. The controller does this in the main checkout, and it has no commit.

## Review Focus

1. **An error right after a sibling that holds its own error** (`<q a={{b +}} c-d="1" />`) must be classified against its real parent, however deep it is. If the walk's path isn't cut back when it moves to the next branch, `c-d` is read as a child of the `{{b +}}` expression and drops to `syntax-error`. Pinned by `reads_the_right_parent_after_a_sibling_with_an_error` (Task 1). A dry run confirmed this test fails if `path.truncate(depth)` is removed.
2. **Thousands of sibling mistakes in one file** must each be reported, in source order, without the per-error sibling scan making it slow. Pinned by `reports_thousands_of_sibling_errors_in_source_order` (Task 1).
3. **`mesh check` on a deeply nested error file** must exit 1 with the located diagnostic, not die from a signal on the main thread's stack. Pinned by `check_rejects_a_deeply_nested_syntax_error_without_crashing` (Task 1).
4. **An attribute name glued to the previous value** (`b="x"c-d="y"`, `b={x}c-d="y"`) is valid spacing (`b="x"c="y"` parses), so it must keep its `hyphenated-attribute-name` code after Task 2 tightens the rule. Pinned in `hyphenated_attribute_name_after_a_multi_byte_character` (Task 2).
5. **Mistakes behind an unclosed root** must show up with their own codes once the root is closed. Pinned by `a_missing_closing_tag_is_the_only_error_reported_for_its_element` (Task 3).

**Known and out of scope:** a *valid* file nested about 5,000 levels deep still overflows the stack in lowering (`mesh-semantic`), exactly as in v0.1. That is not a D17 regression and isn't fixed here. It is a separate follow-up.

- [ ] **Step 5: Replace `collect_regions` with `Region`**

Replace the whole `collect_regions` function and its doc comment:

```rust
/// Pushes every outermost `ERROR` node and every `MISSING` node, in
/// source order. Never descends into an `ERROR`: nested errors belong to
/// the region that contains them.
///
/// Iterative rather than recursive: a deeply nested tree (thousands of
/// levels, one error at the bottom) would otherwise recurse once per
/// level and blow the stack. An explicit stack holds the same walk;
/// pushing each node's children in reverse makes them pop, and so get
/// visited, in source order.
fn collect_regions<'tree>(node: Node<'tree>, regions: &mut Vec<Node<'tree>>) {
    let mut stack = vec![node];
    while let Some(node) = stack.pop() {
        if node.is_error() || node.is_missing() {
            regions.push(node);
            continue;
        }
        if !node.has_error() {
            continue;
        }
        let mut cursor = node.walk();
        let children: Vec<Node<'tree>> = node.children(&mut cursor).collect();
        stack.extend(children.into_iter().rev());
    }
}
```

with:

```rust
/// An error region together with the path from the root down to it.
///
/// Tree-sitter's `Node::parent()` (and `prev_sibling()`/`next_sibling()`,
/// which call it) re-walks the tree from the root on every call, and for
/// a zero-width `MISSING` node it recurses once per level on the way
/// down. On a deeply nested file that is both slow and a stack overflow,
/// so the classifier never calls them: it reads parents and siblings from
/// the path the walk in [`collect`] already holds.
#[derive(Clone, Copy)]
struct Region<'path, 'tree> {
    node: Node<'tree>,
    /// Every ancestor of `node`, root first, so the parent is last.
    ancestors: &'path [Node<'tree>],
}

impl<'tree> Region<'_, 'tree> {
    /// The `n`th ancestor: 1 is the parent, 2 the grandparent, and so on.
    fn ancestor(&self, n: usize) -> Option<Node<'tree>> {
        let index = self.ancestors.len().checked_sub(n)?;
        self.ancestors.get(index).copied()
    }

    fn parent(&self) -> Option<Node<'tree>> {
        self.ancestor(1)
    }

    /// The node `offset` places after this one among its parent's
    /// children (negative for before), counting anonymous tokens too, as
    /// `Node::prev_sibling`/`next_sibling` do.
    fn sibling(&self, offset: isize) -> Option<Node<'tree>> {
        let parent = self.parent()?;
        let mut cursor = parent.walk();
        let siblings: Vec<Node> = parent.children(&mut cursor).collect();
        let index = siblings.iter().position(|n| n.id() == self.node.id())?;
        siblings.get(index.checked_add_signed(offset)?).copied()
    }
}
```
