# MESH v0.3 Pass 4: Completion — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve `textDocument/completion` for tags, props, events, scope names, record members and commands, under D4's contract: derived only from existing facts, deterministic, duplicate-free, stably ordered, and degrading to less rather than to wrong (outline, "Pass 4 — Completion"). This pass:
- adds D4's **position classifier** to `mesh-parser`: what kind of place the cursor is in, read from the tokens before it, pinned shape by shape on real recovery trees (finding B7);
- adds **`mesh_analysis::members`**, the one rule for which members a type has, and makes the checker use it, so completion and `unknown-member` can't disagree;
- derives **candidates** in `mesh_compiler::editor` from the manifest, the canonical analysis, or `analyze_expression` (Pass 3), and nothing else;
- serves them from the compile thread, through Pass 2's held-request rule, as LSP completion items with explicit edit ranges;
- proves the contract, and proves **soundness**: every item offered, once inserted, is accepted by the compiler.

**It does not** complete attribute values, string contents, closing tags, object keys, `$event` or snippets (argument lists); each is left for later and listed in the manual. It doesn't add highlighting (Pass 5).

**Architecture:**

```text
mesh_parser::context_at(source, offset) -> Option<Completion>     (syntax: where is the cursor?)
mesh_analysis::members(manifest, &Ty)                             (semantics: one rule, shared with the checker)
mesh_compiler::editor::candidates(source, offset, template, canonical analysis)
        -> Vec<Candidate>                                         (derived items, in D4's order)
mesh-lsp: completion request → held until the snapshot is compiled → Job::Complete on the worker
        → Candidate → CompletionItem (presentation only)
```

- **`mesh-parser`**: a new module `context.rs` with `pub fn context_at(source: &str, offset: usize) -> Option<Completion>`, editor-only like `recover`. `Completion { pub context: Context, pub replace: Span }`, both `#[non_exhaustive]`; `replace` is the partial name under the cursor, or an empty span at it.
- **`mesh-analysis`**: `pub fn members(manifest: &Manifest, ty: &Ty) -> Option<BTreeMap<String, FieldTy>>`; `Walker::member` is rewritten on top of it.
- **`mesh-compiler`**: `editor::candidates` and `Candidate { label, kind, detail, required, replace }`, plus `CandidateKind` and `Detail`.
- **`mesh-lsp`**: the worker gains a second job kind; a new `complete.rs` converts candidates to items.
- Tasks **P4.1**–**P4.7**, in order.

**Tech Stack:** Rust 1.98.1, MSRV 1.91. No new dependency. `lsp-types` 0.97 has `CompletionParams`, `CompletionItem`, `CompletionItemKind`, `CompletionItemLabelDetails`, `CompletionTextEdit` and `CompletionResponse`.

**Spec:** the outline's invariants I1, I2, I4; D4, D7, D10; findings B2, B7; the recovery spec (its S-shapes, and `analyze_expression`); the Definition of Done's completion items under "Navigation works on the examples" and "It works on broken files", and "Completion keeps its contract".

**Depends on:** Pass 3 merged (`analyze_expression`, `mesh_compiler::editor`), and so Pass 2 (held requests, `CompileResult::analysis`).

**Verification evidence:** every context rule below cites a shape from the recovery spec's table (S1–S18) or one of these, observed on 2026-09-24 the same way:

## As built: departures from this plan

Implemented in one commit. The gate passed. Each place the implementation differs from the plan, and why:

1. **`{compact ? |}` is no context.** The table listed `?` of a conditional under K6. With nothing after it, Tree-sitter makes the `?` an `ERROR` token, so K0's rule (a parent that is an `ERROR`) applies, and completion offers nothing there: less, not wrong. `?` in a conditional that parses is K6, and both are pinned.
2. **A `<` that is an operator is K6, not K1.** `{compact <|}` would otherwise have offered tag names inside an expression. The classifier checks the `<`'s parent.
3. **K2 is read from the text, then checked against the tokens.** In S12 (`on.cl`), Tree-sitter's `ERROR` covers `on.` with no token of its own, so no token says `on.`. `context_at` checks for `on.` right before the name, after whitespace, and then requires K4's scan to find an open tag.
4. **The every-offset test found a panic** in that K2 check: it sliced the source at `offset - 3`, inside the emoji of `unknown-reference-after-emoji`. It compares bytes now. The test also runs `context_at` at the end of every prefix.
5. **`Candidate::detail` is a `String`,** not a `Detail` enum: the only consumer prints it, and the type or signature is already printed by `Ty`'s `Display`.
6. **`read_field` is public,** beside `members`, so a member's detail is its type *as read* (`avatar` is `string?`), by the checker's own rule.
7. **The soundness mutation** (P4.4 Step 3) was run as "offer scope names at the start of a handler", since making `Value` also offer commands doesn't compile (an unreachable match arm is a denied warning). Soundness failed on `compact` offered as a command; the mutation was reverted.
8. **Completion requests aren't held by the test gate.** The gate holds compiles only; a completion job runs as soon as its snapshot is compiled.
9. **In-flight completions are tracked** (`Server::completing`), so `$/cancelRequest` and `shutdown` can answer them, and a late result for one is dropped.

## Global Constraints

- **D4's contract, exactly:** derived, deterministic, duplicate-free, stably ordered, degrading to less. Every rule in this plan that decides *what* to offer names the existing fact it comes from.
- **I1: no second engine.** Which members a type has is `mesh_analysis::members`, which the checker itself uses. Which names a place accepts is the correspondence in Decision 6, and the soundness test (Review Focus 3) checks it against the compiler. `mesh-lsp` converts candidates; it chooses none.
- **I2:** `context_at` and `candidates` are editor-only. `git grep -n "context_at\|candidates" crates/mesh-cli/src crates/mesh-compiler/src/lib.rs` is empty. The CST stays private: only `Completion`, `Context` and `mesh_syntax` values cross out of `mesh-parser`.
- **I4:** the request position becomes a byte offset, and each `replace` span becomes a range, through the document's source map.
- **Never panic on input** (D7). `context_at` is total: any text, any offset, including offsets past the end and inside a multi-byte character (it floors them as the source map does).
- **Changelog, authorship, don't push,** as in Pass 0.
- **Verification gate for every task:** Pass 0's four commands.

## Decisions this plan makes

**The classifier (B7)**

1. **Context is read backwards.** The recovery spec's shapes show why: after `<avatar ` the cursor is in the next `text` node (S5, S6); after `user.` the `.` is an `ERROR` sibling (S1, S3); `on.` is a lone `ERROR` token (S11). So `context_at` looks at the **tokens** before the cursor (Tree-sitter leaves, `ERROR` leaves included, `MISSING` ones and whitespace skipped) and, where it needs to, at the kind of their parent node. It never asks "which node is the cursor in".
2. **The prefix.** If the cursor is inside or at the end of a name-shaped token (an `identifier`, a `tag_name`, or the name part of an `on.` token), that token's span is `replace` and the rules look at the token before it; otherwise `replace` is the empty span at the cursor. *P* below is the token the rules look at.
3. **The rules**, first match wins:

   | Rule | When | `Context` | Shapes |
   |---|---|---|---|
   | K1 | *P* is `<` (not `</`) | `TagName` | S7, S15, S18 |
   | K2 | The prefix token starts with `on.`, or *P* is the `on.` of an `event_binding`, and K4's scan finds an open tag | `EventName { tag }` | S11, S12 |
   | K3 | *P* is `.`, and the token before it ends a `reference` or `member_access` node that ends exactly at the `.` | `Member { object }`, where `object` is that node, lowered | S1, S3, S4, S16, C-b |
   | K4 | Scanning back from *P*, the nearest `<` is followed by a `tag_name` *T*, and between *T* and the cursor there is no `>` or `/>` (real, not `MISSING`), no `{` without its `}`, no unclosed string, and *P* is *T*, a value's closing `"` or `}`, or a lone `ERROR` identifier | `AttributeName { tag: T }` | S5, S6, S8, S10, C-a |
   | K5 | *P* is the `{` of an `expression_block` that is an `event_binding`'s `handler` | `Handler` | S13, C-c |
   | K6 | *P* is the `{` of any other `expression_block`; or `(` or `,` whose parent is a `command_invocation`; `[` or `,` of an `array_expression`; `?` or `:` of a `conditional_expression`; `:` of an `object_member`; or a unary or binary operator | `Value` | S13, C-d |
   | K0 | Anything else, or *P*'s parent is an `ERROR` for K5 and K6 | `None` | S9, C-e, text, strings, closing tags |

   `object` in K3 is always a clean subtree, because it's a whole `reference` or `member_access` node. It's lowered with the parser's existing expression lowering, as Pass 3 lowers expression parts.
4. **K4 runs only after K1–K3,** so `<avatar src={user.` is a member context, not an attribute one.
5. **The tree** is parsed afresh by `context_at`, on the compile thread (Decision 11). It's the same grammar and the same parse `parse` does; nothing is cached across calls.

**Candidates (D4)**

6. **What each context offers, and the fact it comes from:**

   | `Context` | Offers | From | Why there (the analysis rule it mirrors) |
   |---|---|---|---|
   | `TagName` | every component | `Manifest::components` | `Walker::element` resolves a tag against the components. |
   | `AttributeName { tag }` | `tag`'s props, then its events as `on.<event>` | `Component::props`, `events` | `Walker::element` resolves attributes against props and `on.` bindings against events. An undeclared `tag` offers nothing. |
   | `EventName { tag }` | `tag`'s events, by name | `Component::events` | As above. |
   | `Handler` | the template's commands | `Template::component().commands` | `Walker::handler` accepts only a command invocation. |
   | `Value` | the template's scope names | `Template::component().scope` | `Walker::expression` resolves references against the scope; commands there are `command-outside-handler`. |
   | `Member { object }` | `members(manifest, ty)` for the object's type | `mesh_analysis::members` | `Walker::member`, which now calls the same function. |

   The last column is what the soundness test checks.
7. **The object's type** (D4: "from canonical state, or from D3's recovery state when there is no canonical IR"):
   - With a canonical analysis, `analysis.type_at(object.span)`: the type analysis gave that exact expression in its real place.
   - Without one (the file has a syntax error), `analyze_expression(object).type_at(object.span)`: the same walker, on the object alone, in value position (Pass 3's Decision 5).
   - No type either way means no members (D4: "When an expression has no type, member completion offers nothing").
8. **`members`** returns a record's fields after expanding named types at the top level (`relation::expand`), and `None` for everything else: an optional (analysis reports `possibly-absent-access`), `any` (every member is allowed, so no list is true), and every other type. `Walker::member` becomes: `Optional` → the fact; `Any` → `Any`; otherwise `members` → the field or `unknown-member`. The existing typing and checking suites prove the behaviour didn't change.
9. **Order** (D4: "Required props before optional ones; otherwise the manifest's order, which is sorted by name"): props required first, each group by name, then events by name; everything else by name. Items carry that order as `sortText` (a zero-padded index), so a client that re-sorts only does so by what was typed.
10. **Detail.** A candidate carries its declared type (props, fields as read, scope names, event payloads) or a command's parameters, printed by `Ty`'s `Display`, and `required` for props and fields. With no model, a manifest with errors, no configured component, or an undeclared component in `AttributeName`, `candidates` returns an empty list (D4's degradation): every candidate comes from a model.

**Serving it (D10, B2)**

11. **The worker computes completion.** `textDocument/completion` goes through Pass 2's held-request rule; once its snapshot is compiled, the loop sends `Job::Complete { id, identity, text, offset, template, analysis }` to the worker, with the snapshot's `Arc`s, and answers when `Done::Complete` comes back, if the identity is still current (else `ContentModified`). Completion parses and may analyze, so it runs where the stack is known (D7), never on the loop's thread.
12. **Items.** `label`: the name (`on.click` for an event in an attribute context). `kind`: `CLASS` for a component, `PROPERTY` for a prop, `EVENT`, `VARIABLE` for a scope name, `FIELD` for a member, `FUNCTION` for a command. `detail`: the type or signature. `labelDetails.description`: `"required"` for a required prop or field. `textEdit`: replaces `replace`'s range with the label, so tag names with `-` (`user-card`) replace whole. `filterText`: the label. `isIncomplete`: `false`. No snippets, no `insertTextFormat`.
13. **Capabilities:** `completionProvider: { triggerCharacters: ["<", "."], resolveProvider: false }`. Clients also ask while an identifier is being typed.

   - in each case, the published diagnostics are exactly the canonical syntax errors.
3. **Soundness: every item is accepted** (`every_candidate_is_accepted_by_the_compiler`, in `crates/mesh-compiler/tests/editor.rs`). For each context kind, a pair of texts built from the examples: one broken, with the cursor, for `context_at`; one complete, with a hole where the name goes (for `AttributeName`, `<avatar ⟨⟩={user.name} />`; for `Handler`, `on.click={⟨⟩($event)}` with the command's arity; and so on). For every candidate, fill the hole and run `compile_with`: no diagnostic whose span overlaps the inserted name has one of the codes `unknown-component`, `unknown-prop`, `unknown-event`, `unknown-reference`, `unknown-command`, `unknown-member`, `command-outside-handler` or `handler-not-command`. Then **completeness**: for the same contexts, the candidates are exactly the declarations Decision 6 names (set equality), so nothing valid is missing.
4. **The contract** (D4, `crates/mesh-lsp/tests/completion.rs`):
   - `the_same_snapshot_gives_the_same_list`: twice, at every offset of both examples;
   - `no_two_items_share_a_label_and_kind`: at every offset of both examples;
   - `props_are_required_first_then_by_name`, `everything_else_is_by_name`;
   - `no_model_offers_nothing`, `a_broken_manifest_offers_nothing`, `an_unconfigured_document_offers_nothing`, `an_undeclared_tag_offers_nothing`;
   - `an_untyped_object_offers_no_members` (`{usr.}`: `usr` isn't in scope), `an_optional_object_offers_no_members` (`{user.avatar.}`);
   - `a_completion_after_a_change_is_for_the_new_text`, and `a_newer_change_makes_it_content_modified` (Pass 2's rule applied to completion).
5. **One member rule** (`crates/mesh-analysis/tests/members.rs`): `members` on a named record, a nested record, an optional, `any`, a list, a string; and the whole existing analysis suite passes unedited after `Walker::member` moves onto it.
