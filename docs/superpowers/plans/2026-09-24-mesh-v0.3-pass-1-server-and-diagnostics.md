# MESH v0.3 Pass 1: The Server, and Canonical Diagnostics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a `mesh-lsp` binary that publishes canonical diagnostics and quick fixes for `.mprx` files and their manifest, and keeps them current as documents and the manifest change (outline, "Pass 1 — The server, and canonical diagnostics"). This pass:
- turns the `mesh-lsp` placeholder into a library plus a `mesh-lsp` binary, speaking LSP over stdio with `lsp-server` and `lsp-types` (D1);
- meets the crash-safety contract at the protocol boundary (D7);
- keeps each document as immutable snapshots, compiles them off the message loop, and never publishes a stale result (D10);
- takes the manifest and each document's component from explicit configuration, never from a file name (D6, I5), and runs the manifest's lifecycle (D9);
- converts diagnostics through Pass 0's source map (I4), and offers each suggestion as a quick fix;
- proves, fixture by fixture, that what it publishes is exactly `mesh check --format json` (I3).

**It does not** add hover, go-to-definition, completion or editor recovery (Passes 2–4), or highlighting and the setup guide (Pass 5).

**Assumed answer to the outline's one open decision:** the component map is **editor configuration** (`mesh.model` and `mesh.components`), as the outline recommends. If the user decides on a project file instead, only Task P1.3's configuration source changes; the snapshot, lifecycle and publication tasks don't.

**Architecture:**
- **`crates/mesh-lsp`** becomes:
  - a library, `mesh_lsp::run(connection, options)`, which runs the whole server over any `lsp_server::Connection`, so tests can drive it in memory;
  - a thin binary, `src/main.rs`: `Connection::stdio()`, `run`, then join the I/O threads.
- Inside the library, one module per responsibility:

  | Module | Responsibility |
  |---|---|
  | `server` | The message loop, dispatch, and protocol state: before `initialize`, running, after `shutdown`. |
  | `config` | D6's settings: parsing them, and resolving paths against the workspace root. |
  | `uri` | `file:` URI ↔ path, and path ↔ workspace-relative key. |
  | `documents` | Open documents and their snapshots (D10). |
  | `manifest` | D9's manifest snapshots and their dependents. |
  | `worker` | The compile thread. |
  | `convert` | `Diagnostic` → LSP diagnostic, suggestion → code action, through the source map. |

- **Flow:** the loop owns all state and is the only code that publishes. It sends each compile job, tagged with a snapshot identity, to a single worker thread that has an explicit stack size. The worker calls `mesh_compiler::compile_with` or `compile` and sends the tagged result back. The loop publishes the result only if the tag is still the document's current identity; otherwise it drops it (the staleness rule).
- Tasks **P1.1**–**P1.8**, in order. Each leaves a working server that the in-process harness tests.

**Tech Stack:** Rust 1.98.1, MSRV 1.91. New dependencies of `mesh-lsp`:
- `lsp-server = "0.10"`;
- `lsp-types = "0.97"`;
- `crossbeam-channel = "0.5"` (already pulled in by `lsp-server`), for `select!` between the connection and the worker;
- `serde` and `serde_json` (already in the workspace).

On 2026-09-24 these resolved to lsp-server 0.10.0, lsp-types 0.97.0 and crossbeam-channel 0.5.17, and `cargo +1.91.0 check` of a probe crate using them passed. `lsp-types` 0.97's `Uri` is `fluent_uri::Uri`, which has no `to_file_path`, so the `uri` module converts itself. `mesh-cli` gains `mesh-lsp` as a dev-dependency, for the agreement test.

**Spec:** `docs/superpowers/specs/2026-09-24-mesh-v0.3-outline.md`: invariants I1, I3, I4, I5; D1, D6, D7, D9, D10; the Definition of Done's "Canonical diagnostics agree with the CLI", "The lifecycle holds", and the protocol and transport halves of "It doesn't crash". The document half of "It doesn't crash" (the prefix test and fuzzing) is Pass 5's.

**Depends on:** Pass 0 merged: `SourceMap` (P0.1) and the declaration spans (P0.3). The spans aren't used yet, but P0.3's manifest changes land first so this pass doesn't conflict with them.

**Verification evidence:** this plan was **not** implemented in a scratch worktree. The dependency versions, their MSRV and the `lsp-server` API it names (`Connection::stdio`, `Connection::memory`, `initialize_start`, `initialize_finish`, `handle_shutdown`, `Response::new_err`, `ErrorCode`) were checked against the published crates. Everything else is design. Every test must be written first and seen to fail.

## As built: departures from this plan

Implemented in two commits: `d266fb7` (P1.1–P1.7, the server and its tests) and `84a0956` (P1.8, the agreement test and the docs). The gate and the MSRV check passed after each, the test count went from 370 to 439, and the `mesh-lsp` and `mesh-cli` suites passed five runs in a row, which is some evidence that the timing-based tests are stable. Each place the implementation differs from the plan, and why:

1. **The server runs its own protocol state machine, not `lsp-server`'s helpers (Tech Stack, Decision 3, P1.1 Step 3).** The plan named `initialize_start`, `initialize_finish` and `handle_shutdown`. Reading their source showed they break the crash-safety contract: they `unwrap()` their sends, so a client that disconnects mid-handshake panics the server. `initialize_finish` also treats any message other than `initialized` as a fatal protocol error, and `handle_shutdown` does the same for anything but `exit`, where LSP says a request after `shutdown` gets `InvalidRequest`. `server.rs` implements the same three states (before `initialize`, running, after `shutdown`) over the raw `Connection` channels, with the outcomes Decision 3 lists. It also answers a second `initialize` with `InvalidRequest`, which the plan didn't cover.
2. **A message that isn't JSON-RPC stops the server; it isn't answered (outline D7's "malformed LSP request" row).** `lsp-server`'s stdio reader thread stops reading at the first message it can't deserialize: bad JSON, or JSON without the JSON-RPC shape. The server then sees the connection close. It can't answer, because there's no request id to answer, and it can't keep reading. So it stops cleanly, like a closed stdin: no panic, exit status 1. `a_message_that_isnt_json_stops_the_server_cleanly` pins that. A message that *is* JSON-RPC but has malformed parameters still gets `InvalidParams`, as planned. The outline's D7 table and the manual say so.
3. **A valid manifest is published clean when it's loaded (Decision 17 didn't say).** The server publishes an empty list on the manifest's URI whenever a load leaves it with nothing to report, including the first load at `initialized`. That clears diagnostics an earlier session or an earlier broken version left on it; otherwise the editor would keep showing stale manifest errors. After that, it publishes only when the set changes. `a_valid_manifest_is_published_clean_when_loaded` pins it, and the outline's D9 says it.
4. **Tests were written with or after the code, not before (the header's instruction).** P1.1–P1.7 were built together, so no test was first seen to fail against a missing feature. To show the key tests can fail, two mutations were run and then reverted:
   - with the staleness check in `finish` disabled, `an_older_result_never_replaces_a_newer_one` fails;
   - with the negotiated encoding ignored (always counting characters), both agreement tests fail, on exactly the emoji fixture, in both encodings.

   P1.3's two `#[ignore = "needs P1.4"]` tests were never needed, because P1.4 existed when they were written.
5. **The harness is `src/testing.rs`, not `tests/common/mod.rs` (File Structure).** Decision 20 already puts the harness in `mesh_lsp::testing` so `mesh-cli` can share it, and one copy is enough. `tests/common/mod.rs` holds only what `mesh-lsp`'s own tests need: a temporary workspace with the example manifest, and a `codes` helper. The harness gained `latest_publication`, because some tests must skip earlier publications, such as item 3's startup publication.
6. **The agreement test is two tests** (Review Focus 1). `every_fixture_publishes_what_mesh_check_reports_in_utf16` and `…_in_utf8` replace the single named test, so a failure names its encoding.
7. **Changes with ranges are applied (Decision 1 advertises full sync).** A client should send whole documents, but if one sends a ranged change anyway, `apply_changes` applies it through the source map rather than dropping it and ending up with the wrong text. Changes to the open manifest get no version check, since the manifest isn't compiled per version, only reloaded.
8. **Quick fix titles** read `Replace with "user"`. The plan didn't specify them.
9. **Not done: the by-hand editor check (Final verification).** This pass was implemented where no editor was available, so no real editor has run the server yet, and the Neovim example in `docs/manual/mesh-lsp.md` is untested. The protocol, lifecycle and agreement tests drive the server as a client would, and the transport tests run the real binary over stdio, but that isn't the same as a real editor. Pass 5's editor setup guide must include this check, and the manual says so.
10. **`documents` and `manifest` stayed in `server.rs` (File Structure).** The module table named them, but the implementation kept everything in `server.rs` (951 lines), and this list didn't say so until the audit after Pass 1 found it (finding B10). Pass 2's first task split them out, as `server/documents.rs` and `server/manifest.rs`: submodules of `server`, so they share its private state without widening it to the crate.

## Global Constraints

- **I3: publish exactly the compiler's diagnostics.** `convert` maps each `mesh_syntax::Diagnostic` in `CompileResult::diagnostics` (or in `mesh_manifest::load`'s errors) to exactly one LSP diagnostic, in order. No code path filters, merges, reorders or synthesizes diagnostics. A server-side notice (such as "no configured component") goes to `window/logMessage`, never into diagnostics.
- **I4: every range goes through the source map.** `mesh-lsp` has no position arithmetic of its own; `git grep -n "chars()\|encode_utf16\|lines()" crates/mesh-lsp/src` finds nothing that computes a position.
- **I5: no identity from names.** No code in `mesh-lsp` calls `file_stem`, or derives a component from a URI or path, except by looking the path up in `mesh.components`.
- **I1/I2:** `mesh-lsp` calls `mesh_compiler::compile_with`, `mesh_compiler::compile` and `mesh_manifest::load`, and nothing below them.
- **The CLI doesn't change.** `crates/mesh-cli/src` is untouched; only its tests gain the agreement test.
- **Never panic on input** (D7). No `unwrap` or `expect` on anything derived from a message, a document, a file or configuration. Clippy's `unwrap_used` and `expect_used` are enabled at the `mesh-lsp` crate root, with `#[allow]` only where an invariant is local and commented.
- **Changelog, authorship, don't push,** as in Pass 0.
- **Verification gate for every task:** Pass 0's four commands, plus `cargo +1.91.0 check --locked --workspace --all-targets` for P1.1 (which changes `Cargo.lock`) and for any task that adds a dependency.

## Decisions this plan makes

**Protocol and capabilities**

1. **Capabilities advertised at `initialize`:**
   - `positionEncoding`;
   - `textDocumentSync`: `{ openClose: true, change: Full }`;
   - `codeActionProvider`: `{ codeActionKinds: ["quickfix"] }`;
   - `workspace.workspaceFolders`: `{ supported: false }`. Multi-root is a v0.3 non-goal: the first workspace folder, or `rootUri`, is the root.

   `serverInfo` gives `mesh-lsp` and the crate version.
2. **Position encoding.** If the client's `general.positionEncodings` offers `utf-8`, use it. Otherwise, if it offers `utf-32`, use that (mapped to `ColumnUnit::Char`). Otherwise use `utf-16`, the protocol default. The result is fixed for the session.
3. **Protocol states** follow the LSP specification:
   - Before `initialize`, a request gets `ServerNotInitialized` and a notification is dropped, except `exit`.
   - After `shutdown`, a request gets `InvalidRequest`.
   - `exit` ends the loop, with status 0 if `shutdown` came first and 1 otherwise.
   - `lsp-server`'s `initialize_start`/`initialize_finish` handle the handshake, and `handle_shutdown` the shutdown.
4. **Unknown requests** get `MethodNotFound`. **Undecodable parameters** get `InvalidParams`, whose message names the method. **Unknown or undecodable notifications** are logged to stderr and dropped. `$/cancelRequest` is accepted and ignored: every request this pass serves (`codeAction`) answers from existing state, without waiting.

**Configuration (D6)**

5. **Shape.** Both `initializationOptions` and the `workspace/configuration` section `"mesh"` are the same object: `{ "model": "<path>", "components": { "<relative path>": "<component>" } }`. Both keys are optional. Paths are relative to the workspace root and use `/`.
6. **Refreshing.** On `workspace/didChangeConfiguration`:
   - if the client declared `workspace.configuration`, the server requests section `"mesh"` and uses the answer;
   - otherwise it reads `settings.mesh` from the notification.

   Either way, a new configuration generation starts and every open document is recompiled (D9).
7. **Malformed configuration** isn't fatal. Keys of the wrong type are ignored one by one, and each problem is logged once through `window/logMessage` (type `Warning`). A missing root makes relative paths unresolvable: every document is checked without a model, and that is logged once.
8. **Document keys.** A document's key is its path relative to the root, with `/` separators and no `.` or `..` segments. It exists only for `file:` URIs under the root. Other schemes (`untitled:`, virtual documents) and files outside the root have no key, so they are checked without a model (D6). Paths compare exactly; the `uri` module doesn't guess case-insensitivity. That is documented as a limitation on case-insensitive file systems.

**Snapshots, the worker and publication (D10)**

9. **Snapshot identity** is `(document generation, manifest generation, configuration generation)`. The document generation is the server's own counter, bumped on each accepted `didOpen`/`didChange`. It's paired with the client's LSP `version`, which is what gets published. A result is current only if all three parts equal the current ones for that document.
10. **One worker thread,** spawned with an 8 MiB stack, four times the 2 MiB the nesting tests pin the pipeline to (D7: never less). Jobs go through an unbounded channel, and results come back through another. One thread is enough: a compile takes milliseconds (the outline's measurement), and a single worker makes completion order equal submission order. The staleness rule is still enforced, and tested, as if that weren't so.
11. **Debounce.** `didOpen` and any manifest or configuration change compile immediately. `didChange` schedules a compile 150 ms after the latest change to that document; a newer change resets the timer. The loop waits with `crossbeam_channel::select!` over the connection, the results channel and a timer. The delay is a named constant, and tests override it through `Options` (Decision 18).
12. **Publication.** `textDocument/publishDiagnostics` carries the snapshot's LSP `version`. `didClose` publishes an empty list without a version, then drops the document's state. A result that arrives for a closed document is dropped.
13. **A worker panic** is caught (`catch_unwind` around each compile). The loop logs it to stderr and to `window/logMessage` (type `Error`), naming the document and version, and publishes nothing for that snapshot. The previous publication stays visible until the next compile succeeds. It's a bug to fix, not a state to design for (D7).

**The manifest (D9)**

14. **Text source:** the open buffer while the manifest's URI is open in the client, otherwise the file on disk. Disk reads that fail (the file is missing, unreadable, or not UTF-8) are logged, and the model is treated as absent: dependents are checked without a model, and nothing is published on the manifest.
15. **A snapshot** is `Arc<ManifestSnapshot>` holding `Result<Manifest, Vec<Diagnostic>>` and its text, for converting positions. A new generation starts on:
    - an edit to the open manifest;
    - opening or closing it (closing reverts to disk);
    - a watched-file change;
    - a configuration change.

    Each is loaded once with `mesh_manifest::load`.
16. **Watching the disk.** If the client declared `workspace.didChangeWatchedFiles.dynamicRegistration`, the server registers a watcher for the configured manifest path after `initialized` and on every configuration change. Otherwise, disk changes to a manifest that isn't open are seen only on the next configuration change or reopen. That limitation is logged once and documented.
17. **Publishing on the manifest.** The manifest's URI gets:
    - a **broken snapshot's** load diagnostics;
    - otherwise, one `manifest-missing-component` diagnostic per distinct component that an open, configured document names and the manifest doesn't declare. These are the canonical diagnostics from `Manifest::template`, in component-name order.

    It is republished whenever either set changes. Documents whose component is missing, and all documents while the manifest is broken, are compiled with `compile`, without a model (D9).

**Testing**

18. **`Options` for `run`:** `debounce: Duration`, and a `#[doc(hidden)] compile_gate: Option<Receiver<()>>`. With a gate, the worker waits for one message on it before each compile, which lets a test hold a compile back and deliver a newer change first. The binary always passes `Options::default()`.
19. **The harness** (`crates/mesh-lsp/tests/common/mod.rs`) wraps `Connection::memory()` and runs `run` on a thread. Its helpers:
    - `initialize(capabilities, options)`, `open`, `change`, `close`, `configure`, `request`, `shutdown_and_exit`;
    - `next_publication(uri) -> (Option<i32>, Vec<Diagnostic>)`;
    - `quiet(duration)`, which asserts that nothing is published in that time.

    Every wait has a timeout, so a hung server fails a test instead of hanging CI.
20. **The agreement test lives in `mesh-cli`** (`crates/mesh-cli/tests/lsp_agreement.rs`). It is the only crate that can both run the `mesh` binary (`assert_cmd`) and link `mesh-lsp`. It depends on `mesh-lsp` and the harness through `mesh-lsp`'s `#[doc(hidden)] pub mod testing`, which re-exports the harness so it isn't copied.

## Review Focus

1. **Canonical diagnostics agree with the CLI** (`every_fixture_publishes_what_mesh_check_reports`). For every `.mprx` fixture and example, with the configuration the CLI's invocation implies, and every broken-manifest fixture:
   - The published diagnostics equal `mesh check --format json`'s document: severity, code and message, in order.
   - Each range, mapped back through the source map, gives the JSON `byte` offsets.
   - Each suggestion is offered as a quick fix with the same replacement and range.

   The test runs twice, negotiating UTF-16 and UTF-8. A new fixture with characters outside the Basic Multilingual Plane before a mistake makes the two encodings' ranges differ, so a conversion bug can't hide.
2. **Syntax errors stay syntax errors:** for every fixture with a syntax error, the published list is exactly its syntax errors, whatever the model (I3).
3. **No stale publication** (`an_older_result_never_replaces_a_newer_one`). With the gate held, send version 2, then version 3, then release the gate twice: only version 3's diagnostics are ever published, and version 2's result is dropped. The same holds for a manifest edit made while a document's compile is held.
4. **Lifecycle:** `did_open_publishes_that_version`, `a_burst_of_changes_publishes_the_last`, `did_close_clears_diagnostics`, `a_lower_version_is_ignored`, `editing_the_manifest_rechecks_dependents`, `breaking_the_manifest_moves_dependents_to_modelless_checking`, `fixing_the_manifest_restores_model_diagnostics`, `a_missing_component_is_reported_on_the_manifest`, `an_unconfigured_document_is_checked_without_a_model`, `an_untitled_document_is_checked_without_a_model`, `renaming_a_file_does_not_carry_its_component` (close the old URI, open the new one, whose key isn't configured).
5. **Protocol boundary** (D7): each case in the outline's list has a test asserting the defined outcome and that the server still answers a subsequent request.
6. **Transport:** `closing_stdin_stops_the_server` and `closing_stdout_stops_the_server` spawn the real binary. The first closes stdin; the second drops stdout, then sends `didOpen` so the server must write. Both assert that the process exits with status 1, promptly, and that stderr contains no `panicked`.
7. **No position logic in `mesh-lsp`** (the I4 grep), and **no name-derived identity** (I5: `git grep -n file_stem crates/mesh-lsp` is empty).
