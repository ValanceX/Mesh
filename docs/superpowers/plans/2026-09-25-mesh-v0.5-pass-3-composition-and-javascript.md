# MESH v0.5 Pass 3: Composition and JavaScript Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Programs of many templates, and the runtime in JavaScript (outline, "Pass 3"). This pass:
- implements **D7** in the runtime: all seven assembly rules, composite expansion, scope binding, nesting, keys through composites, and dispatch through composites;
- adds the compiler's **program check**, to the Rust API, the CLI and `@valancex/mesh-compiler` (D2, D7);
- builds the runtime for **WebAssembly** and ships **`@valancex/mesh-runtime`**, with the JavaScript value encoding (D5, D9);
- runs the **test host** and **reference renderer** in Node too (D10), and proves **native–WebAssembly parity** (I11);
- builds **the slice** in `examples/slice/`, natively and in Node;
- provides the assembly, parity and slice evidence of the Definition of Done.

**Architecture:**
- **Assembly lives in `mesh-runtime`** (`program` module), as steps 2–4 of program validation. The compiler's program check calls the same function, after loading the manifest the way the compiler always has, so the codes and locations are equal because the code is the same (D7: "with the same diagnostics, codes and locations").
- **`crates/mesh-runtime-wasm`,** a new `cdylib` shaped like `mesh-wasm`: a safe core that takes bytes and returns one result document, and a thin `extern "C"` layer. It links no parser, so it's a separate, smaller module (D9 leaves the choice to this plan: Decision 9).
- **`packages/mesh-runtime`,** `@valancex/mesh-runtime`: `encode.ts` (the value encoding, the only code that walks host values), `engine.ts` (loading, the version handshake, memory, failures, as in the compiler package), `index.ts` (`render`, `dispatch`, `init`, `version`, error classes) and `types.ts` (the render tree, the intent, the host interface and the runtime diagnostics). It encodes and transports, and nothing else (I6, I11).
- **A native harness,** `crates/mesh-runtime/examples/harness.rs`, reads requests on stdin and prints results, taking snapshots and payloads in the same byte encoding JavaScript produces. Node's parity tests run the same requests through both. It's an example, not a CLI command: v0.5 adds no `mesh render`.
- Tasks **P3.1**–**P3.7**, in order. P3.1–P3.2 are Rust only; P3.3–P3.5 are the JavaScript side; P3.6 is the slice.

**Tech Stack:** Rust (MSRV 1.91), `wasm32-unknown-unknown`, TypeScript, `node:test`, `ajv`, `playwright`, as in v0.4. No new Rust dependency; no runtime npm dependency.

**Spec:** the outline's D2 (program check), D5 (the JavaScript encoding and the dispatch lifecycle through composites), D7, D9, D10, I6, I10, I11, I13, I15. Definition of Done: "Programs and assembly", "One evaluator", "The slice", and the composite cases of "Structure, keys and handler identifiers".

**Prerequisite:** Passes 1 and 2 are merged, including P2.8 (or it runs first here).

**Verification evidence:** checked at `33648f3`: `mesh-wasm`'s exports and failure contract (`crates/mesh-wasm/src/exports.rs`); the compiler package's `engine.ts`, its tests (`failure`, `memory`, `version`, `size`, `browser`, `pack`) and `scripts/build-wasm.mjs`; `packages/package.json`'s explicit workspace list; `crates/mesh-cli/tests/packages.rs`'s `PACKAGES` list and `version.ts` check; CI's `wasm` job; `fixtures.rs` ignores subdirectories of `examples/`, so `examples/slice/` doesn't join the check corpus by accident. `examples/components.json`'s `user-card` declares an event, `select`, which D7's rule 6 forbids for a composite, and no scope, so the slice needs a manifest of its own (Decision 14). ## Decisions this plan makes

**Composition (P3.1)**

1. **Assembly** runs D7's rules as program validation's step 4, after the fingerprints: (1) duplicate templates; (2) the root's template; (4) binding every scope name of every composite used as an occurrence, soundly, by `is_assignable(P, S)` or `is_assignable(P?, S)` (Pass 2 already depends on `mesh-analysis`); (5) cycles, found by a depth-first walk of the composite-occurrence graph, reporting every occurrence on a cycle; (6) a composite that declares events; (7) a composite occurrence with children. Every rule reports every violation; the diagnostics are sorted by Pass 0 Decision 20. Unreached templates are checked too, and ignored when rendering.
2. **Expansion** evaluates a composite occurrence's written props in the enclosing template, checks each against its prop's declared type (D8: a composite prop from `any` that doesn't fit is an evaluation diagnostic, `runtime-prop-mismatch`), binds each scope name to its prop's value, an unwritten prop to absent, and evaluates the composite's template in place. The occurrence's key step names the composite, and its template's root node takes the occurrence's position (D4).
3. **Dispatch through composites** (D5 step 7): the handler table records, for each handler, the path of composite occurrences from the root to its node; dispatch re-evaluates those occurrences' props against the render's snapshot, in order, then the handler's arguments in the innermost template. The intent's command is that template's component's (D4: `user-card`'s `selectUser`).

**The program check (P3.2)**

4. **Rust:** `mesh_compiler::check::program(manifest: &str, root: &str, templates: &[&str]) -> Vec<RuntimeDiagnostic>`: `mesh_manifest::load` (its diagnostics, as the runtime reports them), then `mesh_runtime`'s steps 2–4. No artifact (D2).
5. **CLI:** `mesh check-program --model <MANIFEST> --root <NAME> <TEMPLATE>... [--format human|json]`. JSON prints the runtime diagnostics document; human prints each diagnostic as `error[<code>]: <message>` and ` --> <template path>` with the component and the span's line and column when the location has them (a template has no source text to quote). Exit 1 on any diagnostic, 0 with `no errors`.
6. **JavaScript:** `checkProgram({ model, root, templates }): Promise<RuntimeDiagnosticsDocument>` in `@valancex/mesh-compiler`, over a `mesh_check_program` export. The compiler module links `mesh-runtime`'s program module for this; the runtime's evaluator is linked too, unless the size test shows it's worth a feature flag (record the numbers).

**The encoding and the module (P3.3)**

7. **The value encoding** (Pass 0 Decision 9's byte-level form), little-endian, one tag byte per value: `0` absent element, `1` null, `2` false, `3` true, `4` number (8 bytes, the binary64 bits, NaN and `-0` as they are), `5` string (u32 count of UTF-16 code units, then the units), `6` list (u32 count, then each element, `0` for a hole or `undefined`), `7` record (u32 count, then each key as a string body and its value; a property whose value is `undefined` is left out), `8` unsupported (the kind as a string body). A snapshot or payload is one value; an absent payload is a flag outside the value.
   - **Walking:** arrays by `Array.isArray` and index up to `length` (so holes are seen); plain objects (prototype `Object.prototype` or `null`) by `Object.keys`; everything else is unsupported with its kind (`typeof`, or `object:<constructor name>`). The ancestors on the current path are tracked, and a value that is its own ancestor is `8 "cycle"`, so encoding terminates. A value reached twice without a cycle is encoded twice.
   - The encoder makes no MESH judgement: it doesn't know types, doesn't reject NaN, doesn't check surrogates and doesn't look at any MESH name. Rust decodes into `HostValue` (Pass 2 Decision 3) and judges.
8. **Module exports:** the version pair (never changes, I10), `mesh_alloc`/`mesh_free`, `mesh_render` (root, template texts, model, snapshot bytes) and `mesh_dispatch` (the render's root, templates, model and snapshot bytes; the handler identifier; a payload flag and bytes), each returning a status and one result document, JSON rendered in Rust: `{"tree": <render-v1>}` or `{"intent": <intent>}` or `{"diagnostics": <runtime diagnostics document>}`. Template texts cross as one length-prefixed buffer. Test hooks (`test-hooks` feature) add the panic and allocation count as in `mesh-wasm`, and `mesh_test_number_text` for P3.5's oracle test.
9. **Two modules,** `mesh.wasm` in `@valancex/mesh-compiler` and `mesh-runtime.wasm` in `@valancex/mesh-runtime`: a host that renders needs no parser, and a host that compiles needs no evaluator. Neither package depends on the other.

**The package (P3.4)**

10. **The API** (design):

    ```ts
    export function render(input: { program: { root: string; templates: readonly string[] }; model: string; snapshot: Record<string, unknown> }): Promise<RenderResult>;
    export function dispatch(render: Render, handler: string, payload?: unknown): Promise<DispatchResult>;
    export type RenderResult = { render: Render; diagnostics?: never } | { render?: never; diagnostics: RuntimeDiagnosticsDocument };
    export type DispatchResult = { intent: CommandIntent; diagnostics?: never } | { intent?: never; diagnostics: RuntimeDiagnosticsDocument };
    export class Render { readonly tree: RenderTree; /* private: the program's texts, the model, the encoded snapshot */ }
    ```

    A `Render` keeps the snapshot as encoded bytes, taken at render, so later changes to host objects can't reach it (D5). `tree` is parsed from the module's JSON and deep-frozen. `dispatch` refuses a `Render` it didn't make with a `TypeError` (a private field check), which is JavaScript hygiene, not MESH validation; the runtime re-validates the rest (I14). A payload that isn't given and a payload of `undefined` are both absent (D5: "A payload that isn't given is absent"), and the runtime judges whether absence fits the event.
11. **Types:** `RenderTree`, `RenderNode`, `TextRun`, `BoundaryValue`, `CommandIntent`, `IntentArgument`, `RuntimeDiagnostic`, `RuntimeDiagnosticsDocument`, and a `Host` interface documenting D5's obligations (keep each render while its tree is shown; dispatch with the render the renderer drew). A PORT renderer imports only the tree types.
12. **Size budget:** the runtime module's gzipped size is measured and its budget set at the measured size plus 50%, capped at v0.4's 300,000 bytes; `size.test.mjs` enforces it.

**Evidence (P3.5, P3.6)**

13. **Parity** (I11): Node runs every request of P2.7's programs, P2.8's generated snapshots (written by the native property test to `target/` as encoded requests), every input-validation case (with the JavaScript-only kinds built as real JavaScript values), and the slice, through the package and through the native harness, and requires byte-identical result documents. The number oracle: 1,000,000 seeded random bit patterns and the edge list, finite only, through `mesh_test_number_text`, against V8's `String(x)`; a single difference fails the test, and is a bug in the runtime, since §9.7 cites ECMA-262.
14. **The slice** (`examples/slice/`): a manifest with primitives `page`, `text`, `avatar` (with a `click` event whose payload is a record) and `button`, and the composite `user-card` (props `user: User` and optional `compact: boolean`; scope `user: User` and `compact: boolean?`; command `selectUser(user: User)`; no events); `user-card.mprx`; `users.mprx`, the root, using `user-card` twice; snapshot fixtures; and the committed expected tree, HTML, changes and intent (D10). Its templates are compiled by the tests, not committed.

## Review Focus

1. **Every assembly rule** has a test that breaks it, with equal codes and locations from `mesh check-program`, `checkProgram()` and the runtime (the outline's list, whitespace-only children included).
2. **Composition:** a nested composite renders; two occurrences of one composite and of one primitive get distinct keys and handler identifiers; an occurrence with no template renders as a primitive; an unreached template is accepted and ignored.
3. **Dispatch through a composite** gives the composite's command with its evaluated arguments.
4. **Parity:** byte-identical results natively and in WebAssembly for every request; the number oracle agrees with V8 on every value.
5. **I11 in the package:** the review test passes, and a reviewer reading `packages/mesh-runtime/src` against I11's list finds nothing.
6. **The slice** holds natively and in Node, with every committed expected file.
