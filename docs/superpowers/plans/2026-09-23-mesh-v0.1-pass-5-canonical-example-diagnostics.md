# MESH v0.1 Pass 5: Canonical Example & Diagnostic Rendering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish MESH v0.1: rustc-style diagnostic rendering (source snippet + caret), a severity-aware `mesh check` (warnings no longer fail the command), the canonical `user-card.mprx` example, and a fixture corpus under `examples/` driven by a `mesh-cli` integration test.

**Architecture:** `mesh_syntax::Severity` gains a `Display` impl (`error`/`warning`) so every consumer labels severities the same way without matching a `#[non_exhaustive]` enum across crates. A new `mesh-compiler` module, `render.rs`, exposes one pure function, `render_diagnostic(source, path, diagnostic) -> String`, which turns a byte-span `Diagnostic` into a rustc-style block. `mesh-cli` prints every diagnostic through it and exits 1 only if at least one diagnostic is `Severity::Error`. A flat, directory-convention fixture corpus (`examples/fixtures/{pass,fail}/*.mprx` with sibling `.stderr` files) is exercised by one integration test file that runs the real binary.

**Renderer boundary (v0.1 placement decision).** `mesh_syntax::Diagnostic` holds semantic diagnostic data only (`severity`, `message`, `span`). `mesh_compiler::render_diagnostic` is a presentation adapter that formats that data for a terminal. Rendering is deliberately not a method or field on `Diagnostic`. Exposing the renderer from `mesh-compiler` is a v0.1 placement choice, not a claim that terminal presentation belongs in the compiler's semantic model. If later consumers need very different formats (LSP, JSON, editor rendering), presentation can move out without touching `Diagnostic`. v0.1 does not create a crate for this.

**Tech Stack:** Rust 1.98 (workspace crates `mesh-syntax`, `mesh-compiler`, `mesh-cli`), `clap`, `assert_cmd`/`predicates`/`tempfile` (already dev-dependencies of `mesh-cli`). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-09-21-mesh-v0.1-roadmap-design.md` ("Pass 5 — Canonical example and polish", which is also the v0.1 Definition of Done) and `docs/superpowers/specs/2026-09-22-mesh-v0.1-pass-3-5-outline.md` ("Pass 5"). `docs/MPRX-SPEC.md` is the grammar and semantics authority, and this pass changes neither.

## Global Constraints

- **No grammar, AST, parser, or semantic changes.** Pass 5 is integration and polish. `grammar/`, `mesh-parser`, and `mesh-semantic` are not touched.
- **`mesh_compiler::compile`'s signature and `CompileResult`'s fields stay exactly as they are.**
- **`mesh_syntax::Diagnostic` stays pure data** (`severity`, `message`, `span`). Rendering lives in `mesh-compiler` and is never a method or field on `Diagnostic` (see "Renderer boundary" above). The existing `impl Display for Diagnostic` (`message (start..end)`) stays unchanged.
- **No new crates or dependencies.** That includes `codespan-reporting`, `ariadne`, `annotate-snippets`, `unicode-width`, and `walkdir`.
- **Exit codes for `mesh check`:** 1 if any diagnostic has `Severity::Error` or the file can't be read, otherwise 0. Warnings alone never fail the command.
- **Output streams:** rendered diagnostics (errors and warnings) go to **stderr**. `no errors\n` goes to **stdout** whenever the exit code is 0, even when warnings were printed.
- **Newline ownership.** `render_diagnostic` returns exactly one diagnostic block. It owns that block's internal line breaks and returns **no trailing newline**. `mesh check` owns the separation between diagnostics: it writes each rendered block to stderr followed by exactly one blank line (`eprintln!("{}\n", block)`). Never add a trailing newline inside `render_diagnostic`, because that would double the blank lines in every fixture's expected output.
- **Diagnostic order is the order in `CompileResult.diagnostics`.** The CLI never sorts, groups, or filters, so Pass 4b's ordering invariant shows up unchanged in the output.
- **Column semantics (v0.1 contract, do not "fix").** A column is the number of Unicode scalar values (Rust `char`s) before the span start on its line, plus one. It is not a byte count. Tabs are kept verbatim in the source snippet, and the underline's indentation echoes each tab so carets line up in any tab width. v0.1 does **not** compute terminal display-cell width, so wide characters (CJK, emoji) get no special handling and carets after them may appear visually shifted. Width-aware alignment is out of scope for v0.1. Don't add a Unicode-width dependency or change this contract silently.
- **Line endings.** A trailing `\r` (CRLF) is never shown, never counted as a column, and never underlined. A span that starts inside a line ending (on the `\r` or `\n`) renders at the column just past the line's last visible character, with one caret.
- **Multi-line spans underline only their first line**, up to the end of that line's visible text. There's no rustc-style `/`…`|_` multi-line art.
- **The renderer never panics** for any `(source, span)` pair. An out-of-range offset is clamped to `source.len()`. An offset that isn't on a UTF-8 char boundary is floored to the previous one. `end` is raised to at least `start`.
- **Determinism:** output depends only on `(source, path, diagnostic)`. It never depends on terminal width, colour, environment variables, or time. No ANSI colour in v0.1.
- **Commit authorship:** commit messages must follow the repository's established authorship and contributor convention. Don't invent, impersonate, or hard-code an agent or model identity in commit metadata.
- **Verification gate for every task**, run from the `mesh/` repo root. These are the same three commands `.github/workflows/ci.yml` runs:

  ```bash
  cargo fmt --all -- --check
  cargo clippy --workspace --all-targets -- -D warnings
  cargo test --workspace
  ```

  The pass ends with the **Final verification** section after Task 4, which runs this gate plus the repository-hygiene checks.

**Interfaces:**
- Consumes: `mesh_syntax::{Diagnostic, Severity, Span}` (existing).
- Produces:
  - `impl std::fmt::Display for mesh_syntax::Severity`: `Error` → `"error"`, `Warning` → `"warning"`.
  - `pub fn mesh_compiler::render_diagnostic(source: &str, path: &str, diagnostic: &mesh_syntax::Diagnostic) -> String`. It returns one block with **no trailing newline**. Separating blocks is the caller's job (Task 2).

**Output format** (exact; `G` is the line number's width in spaces):

```text
{severity}: {message}
{G}--> {path}:{line}:{column}
{G} |
{line} | {visible source line}
{G} | {indent}{carets}
```

- `line` and `column` are 1-based. Columns follow the column-semantics contract in Global Constraints: `char`s, not bytes, and no display-width handling.
- The visible source line is the line containing the span's start, with any trailing `\r` removed. If it's empty, the line is printed as `{line} |` with no trailing space.
- `indent` has one character for each `char` before the visible span start: a tab stays `\t`, anything else becomes a space.
- `carets` has one `^` per `char` from the visible span start to `min(span end, end of visible line)`, with a minimum of 1.
- The visible span start is `min(span start, end of visible line)`. That's what keeps spans starting on `\r`/`\n` off the line ending.

A note on the string literals above. In a Rust string, a `\` at the end of a line skips the newline **and all leading whitespace on the next line**. So `"...\n \` followed by `--> page.mprx` produces `"...\n --> page.mprx"`: the one space before the `\` is what survives. Line-number lines start at column 0 after `\n\`. Don't hand-reformat these literals. If `cargo fmt` changes them, it only changes whitespace outside the string, which is harmless.

Create `crates/mesh-compiler/src/render.rs`:

```rust
//! rustc-style rendering of [`Diagnostic`]s for terminal output.
//!
//! This is a presentation adapter: `Diagnostic` stays pure data in
//! `mesh-syntax`, and this module only formats it. Living in
//! `mesh-compiler` is a v0.1 placement choice, not a statement that
//! terminal presentation belongs to the compiler's semantic model.

use mesh_syntax::Diagnostic;

/// Renders `diagnostic` rustc-style: a `severity: message` header, a
/// `--> path:line:column` location, and the source line the diagnostic
/// starts on, underlined with carets:
///
/// ```text
/// error: mismatched closing tag: opened with "title", closed with "heading"
///  --> card.mprx:2:3
///   |
/// 2 |   <title>Users</heading>
///   |   ^^^^^^^^^^^^^^^^^^^^^^
/// ```
///
/// Returns exactly one block with no trailing newline — separating
/// blocks is the caller's job.
///
/// Lines and columns are 1-based. Columns count Unicode scalar values
/// (`char`s), not bytes, and deliberately ignore terminal display width:
/// wide characters get no special alignment in v0.1. Tabs before the
/// span are echoed in the underline so carets stay aligned. A span
/// covering several lines is underlined only to the end of its first
/// line, and a trailing `\r` (CRLF sources) is never shown, counted, or
/// underlined. An out-of-range span, or one that splits a multi-byte
/// character, is clamped rather than panicking — a bad span should
/// degrade the snippet, not crash the CLI.
pub fn render_diagnostic(source: &str, path: &str, diagnostic: &Diagnostic) -> String {
    let start = source.floor_char_boundary(diagnostic.span.start_byte);
    let end = source
        .floor_char_boundary(diagnostic.span.end_byte)
        .max(start);

    let line_start = source[..start].rfind('\n').map_or(0, |i| i + 1);
    let line_end = source[start..]
        .find('\n')
        .map_or(source.len(), |i| start + i);
    let line_text = source[line_start..line_end].trim_end_matches('\r');
    let text_end = line_start + line_text.len();
    let line_number = source[..line_start].matches('\n').count() + 1;
    // A span starting inside the line ending (`\r` or `\n`) points just
    // past the last visible character, never into the line ending itself.
    let visible_start = start.min(text_end);
    let column = source[line_start..visible_start].chars().count() + 1;

    let indent: String = source[line_start..visible_start]
        .chars()
        .map(|c| if c == '\t' { '\t' } else { ' ' })
        .collect();
    let underline_end = end.min(text_end).max(visible_start);
    let carets = "^".repeat(source[visible_start..underline_end].chars().count().max(1));

    let gutter = " ".repeat(line_number.to_string().len());
    // Omit the separating space for an empty line so no output line ends
    // in trailing whitespace (fixture `.stderr` files must survive editors
    // that strip it, and `git diff --check`).
    let code = if line_text.is_empty() {
        String::new()
    } else {
        format!(" {line_text}")
    };

    format!(
        "{severity}: {message}\n\
         {gutter}--> {path}:{line_number}:{column}\n\
         {gutter} |\n\
         {line_number} |{code}\n\
         {gutter} | {indent}{carets}",
        severity = diagnostic.severity,
        message = diagnostic.message,
    )
}
```

**Corpus contract (v0.1):**
- **Discovery is non-recursive.** The test lists each directory with a single `fs::read_dir`. `examples/*.mprx` means files *directly* inside `examples/`, and likewise `examples/fixtures/pass/*.mprx` and `examples/fixtures/fail/*.mprx`. The test names them explicitly, so deleting or renaming either one fails instead of quietly shrinking the corpus. `page.mprx` (from Pass 1) is also checked, but only generically.
- `examples/fixtures/pass/*.mprx` must exit 0 with stdout `no errors\n`, and stderr must equal the sibling `.stderr`.
- `examples/fixtures/fail/*.mprx` must exit 1 with empty stdout, and stderr must equal the sibling `.stderr`.

Each `.stderr` file therefore ends with exactly one newline after the last caret line. Don't keep the trailing blank line the CLI prints, because `git diff --check` flags it as a blank line at EOF.

```rust
//! Corpus-driven integration tests: runs the real `mesh` binary over the
//! `.mprx` files in the workspace's `examples/` directory.
//!
//! - `examples/*.mprx` — clean examples; must check clean (exit 0,
//!   `no errors`, empty stderr). `CANONICAL_EXAMPLES` must be among them.
//! - `examples/fixtures/pass/*.mprx` — must exit 0 with `no errors`;
//!   stderr (warnings) must match the sibling `.stderr` file.
//! - `examples/fixtures/fail/*.mprx` — must exit 1 with empty stdout;
//!   stderr must match the sibling `.stderr` file.
//!
//! Discovery is deliberately non-recursive: only files directly inside
//! each of those three directories are found, and files in nested
//! subdirectories are ignored. `mesh check` runs with `examples/` as its
//! working directory and a relative path, so `-->` lines in `.stderr`
//! files read like `fixtures/fail/empty.mprx` wherever the repo is
//! checked out. To add a fixture, place a `.mprx` + `.stderr` pair
//! directly in `fixtures/pass/` or `fixtures/fail/` — no code changes
//! needed.

use assert_cmd::Command;
use std::fs;
use std::path::{Path, PathBuf};
use std::process::Output;

/// The required v0.1 canonical examples, directly inside `examples/`.
/// Named explicitly so deleting or renaming one fails loudly rather than
/// silently shrinking the corpus.
const CANONICAL_EXAMPLES: [&str; 2] = ["user-card.mprx", "users-page.mprx"];

fn examples_dir() -> PathBuf {
    Path::new(env!("CARGO_MANIFEST_DIR")).join("../../examples")
}

/// Every `.mprx` file directly inside `examples/<relative_dir>` (not
/// recursive), as a path relative to `examples/`, sorted so failures
/// report in a stable order.
fn mprx_files(relative_dir: &str) -> Vec<PathBuf> {
    let mut files: Vec<PathBuf> = fs::read_dir(examples_dir().join(relative_dir))
        .unwrap_or_else(|err| panic!("should read examples/{relative_dir}: {err}"))
        .map(|entry| entry.expect("should read a directory entry").path())
        .filter(|path| path.is_file() && path.extension().is_some_and(|ext| ext == "mprx"))
        .map(|path| Path::new(relative_dir).join(path.file_name().expect("has a file name")))
        .collect();
    files.sort();
    // Guards against a moved/renamed directory making the test pass vacuously.
    assert!(
        !files.is_empty(),
        "examples/{relative_dir} should contain at least one .mprx file"
    );
    files
}

fn check(relative_path: &Path) -> Output {
    Command::cargo_bin("mesh")
        .unwrap()
        .current_dir(examples_dir())
        .arg("check")
        .arg(relative_path)
        .output()
        .expect("should run mesh check")
}

/// Checks every file in `relative_dir`, collecting all mismatches before
/// failing so one run reports the whole corpus, not just the first miss.
/// `expected_stderr` returning an empty string means "stderr must be empty".
fn assert_corpus(
    relative_dir: &str,
    expected_code: i32,
    expected_stderr: impl Fn(&Path) -> String,
) {
    let expected_stdout = if expected_code == 0 {
        "no errors\n"
    } else {
        ""
    };
    let mut failures = Vec::new();

    for file in mprx_files(relative_dir) {
        let output = check(&file);
        let stdout = String::from_utf8_lossy(&output.stdout);
        let stderr = String::from_utf8_lossy(&output.stderr);
        let expected = expected_stderr(&file);

        if output.status.code() != Some(expected_code) {
            failures.push(format!(
                "{}: expected exit code {expected_code}, got {:?}",
                file.display(),
                output.status.code()
            ));
        }
        if stdout != expected_stdout {
            failures.push(format!(
                "{}: expected stdout {expected_stdout:?}, got {stdout:?}",
                file.display()
            ));
        }
        if stderr.trim_end() != expected.trim_end() {
            failures.push(format!(
                "{}: stderr mismatch\n--- expected ---\n{expected}\n--- actual ---\n{stderr}",
                file.display()
            ));
        }
    }

    assert!(failures.is_empty(), "{}", failures.join("\n\n"));
}

/// Reads the `.stderr` file next to a fixture; every fixture must have one.
fn stderr_file(relative_path: &Path) -> String {
    let path = examples_dir().join(relative_path.with_extension("stderr"));
    fs::read_to_string(&path).unwrap_or_else(|err| {
        panic!(
            "every fixture needs a .stderr file; could not read {}: {err}",
            path.display()
        )
    })
}

#[test]
fn canonical_v0_1_examples_are_present() {
    let discovered = mprx_files("");
    for name in CANONICAL_EXAMPLES {
        assert!(
            discovered.contains(&PathBuf::from(name)),
            "examples/{name} is a required v0.1 canonical example"
        );
    }
}

#[test]
fn examples_check_clean() {
    assert_corpus("", 0, |_| String::new());
}

#[test]
fn pass_fixtures_exit_zero_with_expected_warnings() {
    assert_corpus("fixtures/pass", 0, stderr_file);
}

#[test]
fn fail_fixtures_exit_one_with_expected_diagnostics() {
    assert_corpus("fixtures/fail", 1, stderr_file);
}
```

`canonical_v0_1_examples_are_present` and `examples_check_clean` together show that each canonical example exists *and* checks clean. The first fixes which files must be there, and the second checks every discovered top-level file, canonical ones included.
