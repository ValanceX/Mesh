# MESH v0.18.0 release notes

*Prepared 2026-10-30 (not yet published: v0.17.0 is the latest release).*

v0.18 gives the units API one word per concept. MPRX already used "instance" for an element of a component and for a repeat's key; the runtime used it again for one occurrence of a component with a unit. The prose already said "occurrence". Units are Provisional, so the cheapest time to rename is before the first outside dependent (direction decision C-4).

## Highlights

- **The rename.** `Render.instances` is `Render.occurrences`; `intent.instance` is `intent.occurrence`; a listed unit's `instance` is `occurrence`; a `units` entry's `"instance"` key is `"occurrence"`; the diagnostic `runtime-unknown-instance` is `runtime-unknown-occurrence`. In Rust: `Render::occurrences`, `occurrences_to_json`, `Occurrence`, `Intent::occurrence()`, `RuntimeCode::UNKNOWN_OCCURRENCE`. The WebAssembly results, `render-v1`'s intent, the specification, the manuals and the conformance vectors (`units/step-N.expected.occurrences.json`) follow.
- **"Instance" keeps its MPRX meanings** (an element of a component; a repeat's key, §9.10). Nothing about the language changes.
- **The old names work for one release**, deprecated, and are removed in the next minor. See below.
- **The diagnostic `runtime-unknown-instance` is retired**, never reused. A host that matched it must match `runtime-unknown-occurrence`.
- The screen (`openScreen`) and the argument names on the intent, both Unreleased on the branch, ship in this release; the screen already said `occurrence`.

## Migrating

| Was | Is |
|---|---|
| `render.instances` / `Render::instances()` | `render.occurrences` / `Render::occurrences()` |
| `each.instance` (a listed unit), `intent.instance` | `each.occurrence`, `intent.occurrence` (Rust: `intent.occurrence()`) |
| `[ { "instance": key, "state": ... } ]` (Rust `Units::from_json`) | `"occurrence"` (the old key is still read; both in one entry is refused) |
| `mesh_runtime::Instance`, `instances_to_json()` | `Occurrence`, `occurrences_to_json()` |
| `runtime-unknown-instance` | `runtime-unknown-occurrence` |

What the runtime *writes* (the JSON of an intent or of the occurrences, the module's result documents) has the new names only. The JavaScript aliases are not enumerable, so deep comparisons and `JSON.stringify` see the new shape. In Rust, `Intent` is Stable and its fields are public, so the `instance` field stays under its old name, `#[deprecated]`, and `Intent::occurrence()` reads it: renaming it or adding a second field would break code that builds an `Intent`. A Rust host that builds `Intent { .. }` keeps compiling (with a deprecation warning for the field). The field is renamed in the release that removes the aliases.

## Compatibility

A program, a manifest, a snapshot and every other document are unchanged. A host that reads `render-v1` intents or the module's result documents by the old property names must read the new ones. The module and the package still have to be the same version.

## North-star scorecard

**M2** (one term per concept): the "instance" collision is removed; M2 stays ◐ while the other collisions remain. Tier 2 (Provisional). No audit regresses.

## Verification

`cargo test --workspace`; the runtime package's tests (a new test for each of the old names in both runtimes); the conformance vectors for units under their new names. Not run in this environment: the runtime package's size test (needs binaryen) and the browser tests.
