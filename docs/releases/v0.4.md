# MESH v0.4.0 release notes

*Released 2026-09-25.*

v0.4 takes MESH outside Rust. `@valancex/mesh-compiler` is the MESH compiler in WebAssembly, for Node and browsers, and `@valancex/mesh-lsp` installs the language server from npm, with no Rust toolchain.

The JavaScript package is the compiler itself, compiled to WebAssembly, not a second implementation. For the same source, manifest and component, it returns exactly the diagnostics document `mesh check --format json` prints. A test compares the two on every fixture, and on seeded mutations of them, and a recorded run compared 100,000.

The language hasn't changed: every v0.3 file means the same thing in v0.4.

## Highlights

- **MESH in JavaScript.** `check({ source, path, model? })` returns the diagnostics, as data, in Node 22 and 24 and in browsers. It's made for generate-check-repair loops: something writes MPRX, MESH checks it, and the diagnostics and their suggestions go back to the writer. The [Using MESH from JavaScript](../guides/using-mesh-from-javascript.md) guide builds one.
- **Positions JavaScript can use.** Every position in the diagnostics document now also gives `utf16`, so `source.slice(start.utf16, end.utf16)` is exactly the text a diagnostic points at, and `utf16Column`, for editors such as Monaco. `mesh check --format json` prints them too.
- **Safe to call again and again.** Memory is released after every check: in a test, 100,000 checks on one instance used no more memory than one pass over the fixtures before them. If the compiler itself ever fails, you get a `MeshInternalError`, and the next check uses a fresh instance. A module of another version is refused with `MeshVersionError` before it's used. About 150 KB gzipped.
- **`mesh-lsp` from npm.** `npm install -g @valancex/mesh-lsp` installs the native server for Linux x64 and arm64 (static, for any distribution), macOS x64 and arm64, or Windows x64. It starts the binary and changes nothing the editor sees. Every binary is built and tested on its own OS and architecture.
- **Tested on Linux, macOS and Windows.** CI now runs the whole test suite on all three.

## Try it

```console
$ npm install @valancex/mesh-compiler
$ node --input-type=module -e 'import { check } from "@valancex/mesh-compiler"; console.log(JSON.stringify(await check({ source: "<page></pag>", path: "page.mprx" })))'
```

```console
$ npm install -g @valancex/mesh-lsp
```

Then follow the [editor setup guide](../guides/editor-setup.md).

## Upgrading from v0.3

- **`mesh check` hasn't changed,** except that `--format json` positions gain `utf16` and `utf16Column`. The document's `version` is still 1: its promise allows added properties, so ignore any you don't know.
- **Rust API, additions:** `mesh_compiler::check` (`Model::load`, `check::source`, `check::run`), the check `mesh check` does, for any program that hosts MESH; and `SourceMap::utf16_offset`.
- **`mesh-lsp` on Windows** now handles verbatim (`\\?\C:\...`) and network-share paths.
- **The npm packages are `@valancex/*`.** The `mesh-language` placeholder is gone. Nothing was published under the old names.
- **The grammar is versioned with MESH,** at 0.4.0.

## Known limitations

- **Diagnostics only.** The JavaScript API doesn't return the compiled tree: its serialized form will be designed with NEXUS and PORT.
- **No language server in the browser.** The JavaScript API gives a browser editor diagnostics; hover and completion there are a later question.
- **Bundlers aren't handled for you.** In a browser, pass `init()` the URL of `mesh.wasm` as your setup serves it.
- **Five platforms have binaries.** Elsewhere, `cargo install --path crates/mesh-lsp` builds the server wherever Rust runs.
- From v0.3, still: configuration lives in each editor, closing tags and record fields have no definition, a diagnostic has one location, manifest edits aren't debounced, and only Neovim's setup is verified.
- From v0.2, still: no presence test for a value that may be absent, no union types, and children aren't checked against components.

## What's next

2. A thin VS Code extension over the npm-installed server.
3. The project file, once configuration across the CLI, the server and the JavaScript API has settled.
