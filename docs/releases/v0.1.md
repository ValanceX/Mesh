# MESH v0.1.0 release notes

*Released 2026-09-24.*

v0.1 is the first release of MESH. It's a **walking skeleton**: MPRX source goes through the whole native pipeline, from Tree-sitter grammar to parser to AST to Semantic IR, and comes out with checked structure and readable diagnostics. It isn't feature-complete. It's the smallest end-to-end toolchain that everything after it can build on.

## Highlights

- **The MPRX v0.1 language.** Elements, attributes, text, `{...}` expressions (literals, references, member access, unary, binary and conditional operators, arrays, objects, command invocations, `$event`), and event bindings (`on.click={...}`). See [Writing MPRX](../guides/writing-mprx.md).
- **`mesh check`.** A native CLI that validates a file and reports every problem, with an exit status you can use as a CI gate. See the [CLI manual](../manual/mesh-cli.md).
- **Diagnostics like the Rust compiler's.** Each problem shows its location, the source line, and a caret underline:

  ```text
  error: mismatched closing tag: opened with "title", closed with "heading"
   --> examples/fixtures/fail/mismatched-closing-tag.mprx:2:3
    |
  2 |   <title>Users</heading>
    |   ^^^^^^^^^^^^^^^^^^^^^^
  ```

- **Structural validation.** It catches mismatched closing tags (an error) and duplicate attributes or event bindings (warnings, where the last occurrence wins). Warnings are reported but don't fail the check.
- **A renderer-independent Semantic IR.** It's available from Rust through `mesh_compiler::compile`. See [Embedding the compiler](../guides/embedding-the-compiler.md).
- **Canonical examples and a fixture corpus.** `examples/user-card.mprx` and `examples/users-page.mprx`, plus `examples/fixtures/`. Each file there has its exact expected output, and the test suite checks that output on every run.

## Install

```console
$ git clone https://github.com/ValanceX/Mesh.git
$ cd Mesh
$ cargo install --path crates/mesh-cli
$ mesh check examples/user-card.mprx
no errors
```

The full walkthrough is in [Getting started](../guides/getting-started.md).

## Known limitations

- **Syntax errors aren't located.** Every syntax error is reported as `syntax error` at `1:1`, wherever the mistake is. Narrowing these spans is the first follow-up planned after v0.1.
- **No semantic checking yet.** References, component names, props, event names, and types aren't checked against a component model. `<user-card user={usr} />` passes.
- **One file per `mesh check`.** There's no `compile` command, no IR output, no `--version`, and no machine-readable (JSON) diagnostics.
- **Columns count characters,** not display width. Carets may look shifted after wide characters (CJK, emoji). A leading byte-order mark counts as one column on line 1.
- **Native Rust only.** The language server (`mesh-lsp`) and the npm packages under `packages/` are placeholders in v0.1. There's no WASM build yet.
- **No integration with NEXUS or PORT yet.** MESH v0.1 stands alone.

## Not in the language (by design)

Comments, subscripts (`a[0]`), optional chaining (`a?.b`), hyphenated attribute names, and arbitrary code. See [Writing MPRX](../guides/writing-mprx.md#what-mprx-deliberately-doesnt-have) for the reasons behind each one and what to use instead.

## What's next

1. Point syntax errors at the actual mistake.
2. Component-aware type checking: resolving references, components, and props against a component model.
3. Editor support through `mesh-lsp`, reusing the compiler.
